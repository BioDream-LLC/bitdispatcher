Osa 1

Hälyttäminen

Päivystäjän näyttö ja kaikki, mitä siltä tehdään: puhelut, tehtävät, yksiköt, kartta ja komentorivi.

Luku 1

Aloittaminen

bitdispatcher on hätäkeskuksille (911) tarkoitettu tietokoneavusteinen hälytysjärjestelmä (CAD): yksi ohjelma, jolla on oma verkkokäyttöliittymänsä. Se luo ja seuraa tehtäviä, suosittelee yksiköitä tieverkon ajoajan perusteella, näyttää yksiköt, puhelut ja tehtävät hälytyskartalla ilmakuvineen, antaa kenttämiehistöille mobiilipäätteen ja tallentaa jokaisen toimen väärentämisen paljastavaan tapahtumalokiin, josta raportit rakennetaan.

Ensimmäinen tunti

  1. Sign in järjestelmänvalvojana ensimmäisellä käynnistyksellä tulostetulla salasanalla ja valitse Administrator. Katso Sisäänkirjautuminen (luku 3).
  2. Tallenna kartta: Admin › Map, valitse keskipiste ja säde, paina Record. Noin kaksi minuuttia 100 mailille. Open Map (luku 108)
  3. Asemat ja yksiköt: missä yksiköt sijaitsevat ja mitä ne ovat. Open Stations (luku 104) Open Units (luku 103)
  4. Tehtävätyypit ja hälytyskortit: mitä kukin tehtävätyyppi tarvitsee. Oletukset ovat järkevä lähtökohta. Open Call types (luku 106)
  5. Käyttäjät: päivystäjät, esimiehet ja kenttämiehistöt. Open Users (luku 113)
  6. Puhelujen käsittely: yhdistä BitVoice tai ohjaa minkä tahansa puhelunkäsittelyjärjestelmän ALI-syöte ja EIDO bitdispatcheriin. Open Integrations (luku 111)

Admin › Setup checklist seuraa näitä vaiheita ja kaikkea muuta, mikä edeltää ensimmäistä live-puhelua, ja Admin › Go-live check testaa tuloksen. Katso Itsepalvelukäyttöönotto (luku 97). Open the checklist (luku 98)

bitdispatcher neuvoo; päivystäjä päättää. Mikään toiminto ei hälytä yksikköä, sulje tehtävää tai muuta kiireellisyyttä itsekseen.

Esittelytila

Kun bitdispatcher käynnistetään -demo-valinnalla, se luo kuvitteellisen viranomaisen Roanoken (Virginia) kartalle (asemat todellisissa asemasijainneissa, keksityt yksiköt). bvsim:n, simuloidun BitVoicen, avulla puhelut soivat ja radiot ilmoittavat sijainteja; kaikki simuloitu on merkitty SIMULATED.

Luku 2

Installing it

Tämä luku muuttui käännöksen jälkeen ja näytetään englanniksi, kunnes käännös on päivitetty.

bitdispatcher runs as a service on one computer, and every console opens it in a browser. Each installer sets it up to start with the computer, before anyone signs in, and shows the first administrator's password once, at the end. Upgrading means running a newer installer: the records, the settings and the users are kept. Uninstalling keeps the records unless you confirm twice that they should go.

There is no release to download yet. Build the installers from the source on any computer with Go (see the README): make windows (needs NSIS), make linux and make macos (on a Mac) write them to the bin folder.

In every case the records folder is closed to everyone but the service and administrators: it holds criminal justice and personal information. The service listens on port 8443 (HTTPS) unless you choose another.

Windows

Run bitdispatcher-setup.exe and approve the administrator prompt. The pages: licence, what to install, the folder, Settings (the port and the records folder; a port another program holds is refused), and the First sign-in password. It adds a firewall rule for domain and private networks, and Start menu entries: bitdispatcher, its manual, and Reset admin password. It is removed from Settings › Apps.

For IT, a silent install: bitdispatcher-setup.exe /S /PORT=8443 /DATA=D:\bitdispatcher /NOFIREWALL (each option may be left out). A silent install shows no password: run Reset admin password afterwards. A silent uninstall keeps the records.

Linux

With the package manager: sudo apt install ./bitdispatcher_VERSION_amd64.deb or sudo dnf install ./bitdispatcher-VERSION-1.x86_64.rpm. The password is printed at the end. Without one: unpack the .tar.gz and run sudo ./install.sh, with --port 9443 for another port and --open-firewall to open it in ufw or firewalld; sudo ./uninstall.sh removes it, --purge deletes the records after you type DELETE twice.

Change the port or the records folder in /etc/default/bitdispatcher, then sudo systemctl restart bitdispatcher. A lost password: sudo systemctl stop bitdispatcher, sudo -u bitdispatcher bitdispatcher reset-password -data /var/lib/bitdispatcher admin, then start it again.

macOS

Open the .pkg and follow it. At the end a dialog shows the password, with Copy password and Open bitdispatcher. If port 8443 is taken it uses the first free port from 9443 and says so. It keeps the Mac awake while the service runs (a dispatch server must answer at any time; the display may still turn off): set BITDISPATCHER_KEEP_AWAKE=no in the settings file to let it sleep. If macOS's firewall is on, bitdispatcher is allowed through it.

Applications › bitdispatcher holds four things: bitdispatcher opens the console, Reset admin password, Uninstall bitdispatcher (it asks twice before deleting the records) and the manual. From Terminal: sudo installer -pkg FILE -target / installs without dialogs and leaves the password in /usr/local/etc/bitdispatcher.first-sign-in for root to read once; delete that file afterwards. After changing the settings file: sudo launchctl kickstart -k system/com.biodream.bitdispatcher.

The certificate

On first start bitdispatcher makes its own certificate, so each browser warns once until it trusts it. Give it one your network trusts with the -tls-cert and -tls-key options (on Linux and macOS in BITDISPATCHER_FLAGS in the settings file).

What has been tested

  • Windows: installing, three upgrades, the password reset and uninstalling, on one Windows desktop computer; and on every change, a silent install, upgrade and uninstall on Windows Server 2022 in CI.
  • Linux: the Intel .deb, .rpm and .tar.gz in Debian 12 and Red Hat UBI 9 containers running systemd (install, upgrade, reset, remove); the Arm ones in the same containers on an emulated Arm processor, not yet on Arm hardware; the .deb on Ubuntu 24.04 in CI.
  • macOS: installing, two upgrades, opening the console, the password reset and uninstalling with the records kept, on one Apple silicon Mac with macOS 26; in CI also a reinstall over the kept records and a full removal. Not yet on an Intel Mac, and not with macOS's firewall on.
  • Not signed. Windows SmartScreen warns about the installer, and macOS asks before opening a downloaded .pkg (System Settings › Privacy & Security › Open Anyway). Signed installers need code-signing certificates, which BioDream has not bought yet.

Kertakäyttökoodit. Kun viranomainen vaatii niitä (Settings › Roles and sign-in), ensimmäinen sisäänkirjautuminen näyttää QR-koodin: skannaa se millä tahansa todennussovelluksella ja kirjoita sen kuusi numeroa. Luku 4

Puhelun kirjaus: hätäkeskuspäivystäjän työtila

Verkkokäyttöliittymässä: /taker

Rauhallinen työtila puheluille: puhelulista vasemmalla, käynnissä olevat puhelut sen vierellä, kymmenen välilehteä yläreunassa, joista vain valittu näytetään, sekä puhelu (sen sijainti, litterointi ja mitä kuultiin) ja narrative aina oikealla.

Ylhäältä alas, siinä järjestyksessä kuin puhelu käsitellään

  1. Puhelu liittyy itse. Työpisteelläsi vastattu puhelu avautuu puhelun kirjaukseen heti ANI:nsa, ALI:nsa ja mahdollisten täydentävien sijaintien kera, kukin lähteineen. Puhelun toista valintaa ei tarvita. Paikalle tullut asiakas tai radioilmoitus kirjoitetaan ilman puhelua.
  2. Tehtävän sijainti ensin (katso Sijainnit ja paikka (luku 38)): osoite, sen piste kartalla, miten se vahvistetaan (vahvistettu osoitepiste, arvioitu väli, soittajan laite, karttapiste tai pakotettu tälle tehtävälle) ja paikka sen sisällä: yrityksen tai rakennuksen nimi, kompleksi, rakennus, kerros, asunto tai huone ja sisäänkäynnin tai portin detalji. Vahvistetun paikan merkinnät näkyvät heti, ennen puhelun lähettämistä, joka välilehdellä.
  3. Soittaja ja takaisinsoittonumero, luettu takaisin ja kuitattu vahvistetuksi.
  4. Puhelutyyppi (kirjoita koodi tai sana; nuolet ja Enter valitsevat), kiireellisyys ja modifiers (osa nostaa kiireellisyyttä, osa lisää ilmoitettavia henkilöitä; virkamiesturvallisuuteen liittyvät näkyvät punaisina).
  5. Send (F4 tai Ctrl+Enter). Narrative oikealla ottaa kommentteja koko ajan: Enter lisää kommentin aikoineen, toista painiketta ei ole. Ennen lähettämistä kirjoitetut kommentit menevät puhelun mukana.

Kun jotain puhelun tarvitsemaa puuttuu, viesti nimeää sen, ja kohdistin siirtyy kyseiseen kenttään. Ainoa, mikä puhelulla pitää olla lähetettäväksi, on sen tyyppi; vahvistamaton tai pakotettu sijainti ei koskaan pidättele sitä.

Useita käynnissä olevia puheluja

Mitä taulu näyttää

Joku, jolla on pääsy vain joihinkin viranomaisiin, näkee vain oman osansa jaetusta taulusta: kyseisten viranomaisten tehtävät ja yksiköt, tehtävät joilla ei ole vielä viranomaista, muiden viranomaisten yksiköt jotka on lähetetty heidän tehtäviinsä, ja 911-puhelut kunnes niistä tulee toisen viranomaisen tehtävä. Jokainen yksikkö säilyttää kotiviranomaisensa: tehtävään lähetetty toisen viranomaisen yksikkö näkyy avustavana itsestään. Sulje luokituksella (CL Handled); yksiköt, jotka ovat yhä siinä, muuttuvat käytettävissä oleviksi. Esimiehet voivat avata uudelleen (RO #26-000123 reason).

Replay (esimiehet, suljetulla tehtävällä) toistaa sen tapahtumalokista: yksiköt liikkuvat kartalla tallennettuja sijaintejaan pitkin (noin 30 sekunnin välein) samalla kun aikajana täyttyy, nopeudella 10×–120×, liukusäätimellä mihin tahansa hetkeen.

Luku 20

Yksikkösuositukset

Valitulle tehtävälle bitdispatcher rakentaa suosituksen hälytystyypin tehtäväkortin pohjalta: kullekin riville ("3 × engine", "1 × als") ne käytettävissä olevat yksiköt, joilla on kyseinen valmius, lähin ensin. Tehtävällä jo olevat yksiköt täyttävät rivit ensin, ja harvinaiset valmiudet täytetään ennen yleisiä, jotta monikäyttöistä yksikköä ei käytetä siellä, missä toinenkin riittäisi.

  • Ajoajat tulevat tallennetusta tieverkosta: merkityt tai tyypilliset nopeudet, yksisuuntaisia katuja noudatetaan, yksikön tuoreesta AVL-sijainnista tai sen asemalta. Perustelu kertoo sen: "1.7 mi by road, 4 min via Franklin Road".
  • Suljetut tiet ja liikenne lasketaan mukaan heti: ajo kiertää suljetun tien (luku 25), ja tie, jonka reaaliaikainen liikenne ilmoittaa hitaaksi, vie kauemmin. Suosituksen alla oleva lähderivi kertoo, milloin ne muuttivat sitä ("around 1 road closure, with live traffic").
  • Tallennetun kartan ulkopuolella tai kun väliltä puuttuu tie, aika on linnuntie-arvio ja se merkitään ~.
  • Toista asemaa peittävä yksikkö asetetaan järjestykseen sen sijoituspaikan mukaan.
  • Huomautukset varoittavat, kun millään yksiköllä ei ole jotakin valmiutta (harkitse virka-apua) tai kun yksiköiden lähettäminen jättäisi aseman tyhjäksi.

Suositellut yksiköt valitaan; Dispatch (Ctrl Enter, tai REC) lähettää ne. Napsauta yksiköitä muuttaaksesi valintaa, Use recommendation palataksesi siihen, tai kirjoita D E1 M2. Kirjanpito tallentaa, mitä suositeltiin ja mitä lähetettiin.

Luku 21

Neuvoa-antavat ehdotukset

Tehtävän vieressä ja Situation-paneelissa neuvoa-antava paneeli voi ehdottaa jotain: kaksi tehtävää, jotka voivat olla sama, puhelu joka voi koskea avointa tehtävää, sanat jotka eivät sovi tehtävätyyppiin ("savu" palohälytyksellä, "ei hengitä" kaatumisella), toistuva osoite, prioriteetti 1 yhä ilman yksikköä, paikalla oleva yksikkö josta ei ole kuulunut.

  • Miksi: avaa ehdotus nähdäksesi näytön, johon se nojasi (lähteineen: yksikkö, soittaja, päivystäjä, kone), mitä se oletti puuttuvaksi, ja säännön selkokielellä.
  • Cannot determine on vastaus: kun samanpainoiset lähteet ovat eri mieltä ("savu" ja "ei savua" kahdelta soittajalta), se kertoo siitä ja sinä päätät.
  • Accept suorittaa ehdotetun komennon sinuna (muuta tyyppi, liitä puhelu, hälytä suositus) tai vain merkitsee sen. Reject yhden napsautuksen perustelulla; sitä ei näytetä uudelleen. Molemmat kirjataan.
  • Se vain neuvoo. Se ei koskaan yhdistä, luokittele uudelleen, priorisoi uudelleen tai hälytä itsekseen, ja ydinhälyttäminen toimii samoin, kun se on pois päältä tai alhaalla.

Kun päivitys tuo uuden säännön (kuten *Silent or abandoned 911 call*), Admin › Advisory panel tarjoaa sen sääntöjen yläpuolella: Add it, sitten Save version. Tallennettu koodikirja ei koskaan muutu itsekseen.

Luku 24

Hälytyskartta

Kartta piirretään bitdispatcherin omasta tallennetusta kartasta (luku 108): tiet luokittain reittikilpineen ja yksisuuntaisuusnuolineen, piiri- ja kuntarajat, talonumerot ja paloposti katutasolla, palokunta, poliisi, ensihoito ja sairaalat omin värein.

  • Search (oikealla ylhäällä): osoite (2001 Crystal Spring Ave), risteys (Orange & Williamson, and, / tai at), katu tai paikka. Nuolinäppäimet ja Enter; Uusi tehtävä tuloksesta. Talonumero, jota ei ole rekisterissä, tarjoaa lähimmät numerot samalta kadulta.
  • Napsauta hiiren oikealla missä tahansa: mitä tässä on (lähin osoite tai tie), Uusi tehtävä tähän, Close a road from here (sulje tie tästä) ja Close the roads around here (sulje tiet tämän ympäriltä) (Teiden sulkemiset (luku 25)), sekä Näkymät tähän paikkaan (luku 28), kun palveluntarjoaja on käytössä.
  • Suljetut tiet piirretään punaisin katkoviivoin, ja liikenteen hidastumat keltaisella, oranssilla ja punaisella niiden alle; napsauta suljettua tietä nähdäksesi syyn, ja Lift.
  • Routes: valitulle tehtävälle kunkin suositellun, valitun ja osoitetun yksikön tiereitti ja sen saapumisaika yksiköllä.
  • Day / Night vaihtaa väripaletin; Photos (F7) asettaa ilmakuvat katujen alle; 3D nostaa rakennukset pystyyn (OpenStreetMapin kerrokset, missä ne on kartoitettu) ja kallistaa kartan, ja oikealla vedolla sitä käännetään; Fit all näyttää jokaisen yksikön ja tehtävän; OOS ja Stations näyttävät tai piilottavat ne.
  • Katkoviivainen syaaninvärinen viiva on tallennetun kartan reuna: sen takana näytetään verkkokartta vaimennettuna, ja ajoajat ovat arvioita.
Luku 25

Teiden sulkemiset ja liikenne

Suljettu tie muuttaa ajoajat ja yksikkösuositukset heti: reititin kiertää sen ilman, että karttaa rakennetaan uudelleen.

  • Sulje tieosuus: napsauta karttaa hiiren oikealla tien kohdalta, Close a road from here, napsauta sitten suljettua osuutta pitkin ja Done. Kerro miksi, mihin asti (tyhjä: kunnes joku poistaa sen), kiertotie, ja merkitäänkö se valitulle tehtävälle.
  • Sulje alue: napsauta hiiren oikealla, Close the roads around here, ja anna säde: jokainen tie, josta jokin osa on ympyrän sisällä, suljetaan (tulva, tulipalo, tapahtumapaikka).
  • Suljetut tiet piirretään punaisin katkoviivoin. Napsauta jotakin nähdäksesi syyn ja mistä lähtien, ja Lift avataksesi sen uudelleen. Sulkeminen, jolla on päättymisaika, poistuu itsestään.
  • Yksikkö voidaan silti lähettää suljetulla tiellä olevaan paikkaan: ajon alku- ja päätepistettä ei koskaan evätä, vain niiden väliset tiet.
  • Miehistöt näkevät nyt suljetut tiet kiertoteineen mobiilipäätteellä (luku 48).
  • Reaaliaikainen liikenne, kun virastolla on syöte (Road closures & traffic (luku 89)), hidastaa ilmoittamansa tiet: tien ajoaika on sen tallennettu aika kerrottuna sillä, kuinka paljon hitaampi se on, enintään kymmenkertaiseksi. Suosituksen lähderivi kertoo, milloin liikenne ja sulkemiset muuttivat sitä.
  • Jokainen sulkeminen, muutos ja poisto on kirjanpidossa tekijään kohdistettu tapahtuma.
Luku 26

Tehtävän lähellä olevat kamerat

Kun virasto on ottanut kamerat käyttöön (Kamerat (luku 90)), karttasijainnin sisältävä tehtävä luettelee Cameras near (lähellä olevat kamerat): viraston kamerat sen säteen sisällä, paikkaa kohti katsovat ensin, etäisyyksineen ja tietoineen siitä, katsovatko ne tähän suuntaan.

  • Paina jotakin: se kysyy miksi (tehtävä tai syy), ja avaa sen sitten. Pysäytyskuvan sisältävä kamera näyttää, mitä se näkee nyt, päivitettynä 5 sekunnin välein; reaaliaikaisen näkymän sisältävä avaa sen kamerajärjestelmässä, joka kirjaa sinut itse sisään.
  • Jokainen avaus tallennetaan tietoineen siitä, kuka, milloin, miksi ja mikä tehtävä, ja se tulee tehtävän aikajanalle. Esimiehet näkevät tallenteen kohdassa Admin › Cameras (luku 90).
  • bitdispatcher ei säilytä videota eikä tallenna mitään kamerasta; pysäytyskuva haetaan kameran avanneelle henkilölle ja vain puoleksi tunniksi.
Luku 27

Ilmakuvat

Päivystäjät löytävät paikkoja kattojen avulla ("valkoinen talo kirkon takana"). Kun Photos on päällä (F7 tai painike kartalla), ilmakuvat ovat pohjana ja kadut, nimet ja talonumerot piirretään niiden päälle.

  • Kuvat tallennetaan Admin › Map -osiossa: täysi tarkkuus keskipisteen lähellä, vähemmän tarkkuutta reunaa kohti. Lähemmäs kuin mitä tallennettiin zoomaaminen suurentaa sen alla olevaa kuvaa, joten kartta ei koskaan mene tyhjäksi.
  • Painikkeen vieressä oleva merkki kertoo, milloin kartan keskipisteen kuva otettiin, missä lähde sen julkaisee ("2023, 12 inch ortho"): vanhaa kuvaa ei koskaan oteta tämän päivän kuvasta.
  • Siellä missä mitään ei ole tallennettu, palvelin hakee kuvan pyydettäessä ja säilyttää sen, ellei sitä ole kytketty pois.
Luku 28

Näkymät: paikka joka suunnasta

Ilmakuvat näyttävät katon. Views näyttävät edustan, takaosan ja sivut: missä takaovi on, aita, portaat, kummalla puolella paloposti on.

  • Views tehtäväpaneelissa (sijainnin vieressä), hätäkeskuspäivystäjän Hazards-välilehdellä, miehistöjen mobiilipäätteellä (luku 48) ja hiiren oikealla kartalla.
  • N E S W: neljä vinoilmakuvaa, pohjoiseen, itään, etelään ja länteen katsoen, viranomaisen omasta EagleView-lisenssistä. Pohjoiseen katsominen näyttää rakennuksen eteläsivun. Nuolinäppäimet kääntävät kompassia.
  • Street-kuvat, jotka katsovat paikkaan, lähin ensin ja enintään kaksi suuntaa kohden, Panoramaxista tai Mapillarysta (avoimet kuvat, CC-BY-SA, kattavuus riippuu siitä, kuka on kuvannut kadun).
  • Pre-plan-kuvat: viranomaisen omat kuvat kohteesta (Knox-laatikko, kaasun sulku, takasisäänkäynti), offline ja tällä palvelimella. Miehistöt lisäävät niitä päätteeltä laitteen kameralla, päivystäjät ja järjestelmänvalvojat täältä tai Kohteet (luku 117)-osiosta; esimiehet poistavat ne.
  • Jokainen kuva kertoo, mistä se tuli ja milloin se otettiin, joten vanhaa kuvaa ei koskaan oteta tämän päivän kuvasta. Laajennuspainike näyttää sen täydessä koossa.
  • Google Street View, kun sitä tarjotaan, avaa Googlen uudelle välilehdelle; mitään Googlesta ei näytetä bitdispatcherin sisällä.
Paikan etsiminen kertoo palveluntarjoajalle, missä tehtävä on. Kukin palveluntarjoaja on pois päältä, kunnes järjestelmänvalvoja kytkee sen päälle Integraatiot (luku 111)-osiossa, ja kuvat kulkevat tämän palvelimen kautta, joten avaimet eivät koskaan päädy selaimeen.

Luku 31

Haku: tehtävät, BOLOt, henkilöt, ajoneuvot ja yksiköt

Yksi haku (suurennuslasi tilarivillä tai Recall klassisissa näppäimissä) tehtävien (numero, tyyppi, osoite, narratiivi ja kommentit), viestien ja BOLOjen (jokainen versio), henkilöiden (nimet missä järjestyksessä tahansa, aliakset, syntymäajat, puhelimet, osoitteet, tunnisteet, kuvaukset), ajoneuvojen (rekisterikilpi, osittainen rekisterikilpi merkillä ? merkille jota et tiedä, VIN, merkki, malli, väri), liitteiden (tiedostonimet, kuvatekstit ja niiden sisällä olevat sanat: pelkkätekstitiedostot, PDF:ien teksti ja kuvissa olevat sanat missä palvelin lukee ne) ja yksiköiden (tunnus, radiotunnus, keitä on kyydissä) halki.

  • Tulokset ryhmitellään, suodattimilla lajeille, viranomaiselle, päiville ja tilalle.
  • Kukin kertoo miksi se osui (sama rekisterikilpi, osittainen VIN, jaettu puhelin, samankaltainen kuvaus, *in the file's text* ympäröivine sanoineen) ja kuinka vahvasti: exact, partial tai similar (samankaltaiset kirjoitusasut pyydettäessä).
  • Possible matches merkitään sellaisiksi: haku ei koskaan yhdistä henkilöä, ajoneuvoa tai tehtävää mihinkään.
  • Vanhentuneet, päivitetyt ja perutut BOLOt kertovat siitä suuraakkosin; vanha varoitus ei koskaan näytä ajankohtaiselta.
  • Haet niitä viranomaisia, joita katat ja seuraat; beyond my agencies vain siellä missä saat työskennellä niille, ja jokainen tulos nimeää viranomaisensa. Alaikäisten nimet ja lääketieteelliset muistiinpanot pidätetään niiltä, joilla ei ole oikeutta, eikä mitään rajoitettua lasketa tai näytetä.
  • Jokainen haku ja jokainen siitä avattu tietue kirjataan tapahtumalokiin.

Unit recall (tuloksista löytyvästä yksiköstä tai yksikön History-näkymästä): yksi yksikkö ajanjaksolta, yhdellä aikajanalla: sen tilat ja ulosmerkinnät, tehtävät tyyppeineen ja osoitteineen, kuka miehitti sen ja missä roolissa, tilatarkastukset, viestit ja missä se oli AVL:n tai radion mukaan. Rajaa sitä vastaajan, tilan tai tehtävän mukaan; lataa se CSV-muodossa.

Luku 32

Hälytykset, rekisterikilpien lukijat ja laukausten tunnistus

Hälytysyhtiöt, rekisterikilpien lukijat ja laukausten tunnistus lähettävät hälytyksensä bitdispatcheriin (Admin › Integrations; sopimus on docs/ALERTS.md). Jokainen saapuu 911-puhelujen luetteloon puheluna, data only (vain tiedot), siten että sen sisältö näkyy yhdellä silmäyksellä: hälytystyyppi ja vyöhyke, VERIFIED kun hälytysyhtiö varmensi sen, rekisterikilpi ja sen etsintälista, laukausten määrä.

  • Valitse se: tehtäväpaneeli näyttää kaiken, mitä lähettäjä antoi (kiinteistö, tili, lupa, avainhenkilö, operaattorin takaisinsoittonumero, kamera ja suuntima, linkki lukijan kuvaan).
  • Luo tehtävä siitä tai liitä se johonkin, kuten mistä tahansa puhelusta; viraston omat hälytys- ja laukaukset-tyypit ehdotetaan, kun niitä on.
  • Lähettäjän päivitys muuttaa samaa puhelua; hälytysyhtiön cancel (peruutus) tulee tehtävälle prioriteettihuomautuksena.
  • Hälytysyhtiöille kerrotaan, mitä niiden hälytykselle tapahtui: hyväksytty, lähetetty, paikalla, suljettu.
  • Jokainen hälytys tarkistetaan viraston permit register -lupaverekisteristä: *Alarm permit P-1: valid*, *EXPIRED*, *SUSPENDED*, tai *none on the register*. Osoitteen väärät hälytykset viimeisen vuoden ajalta lasketaan; viraston rajalla huomautus sanoo REPEAT FALSE ALARMS (Hälytysyhtiöt & luvat (luku 91)).
  • Phoned alarm (puhelimitse ilmoitettu hälytys) (911-puhelujen yläpuolella): kun hälytysyhtiön operaattori soittaa puhelimitse, kirjoita sen hälytys hälytyskortille (yhtiö, operaattori, tapahtumanumero, hälytys, vyöhyke, kiinteistö, osoite, lupa, avainhenkilö). Se tulee jonoon kuten lähetetty, samoin tarkistuksin, ja kertoo, kuka sen kirjasi.
  • Hälytys, johon kukaan ei reagoi, poistuu jonosta 30 minuutin kuluttua; se jää kirjanpitoon.
ASAP over Nlets, kansallinen hälytysten standardi, ei ole vielä kytketty: se tarvitsee standardin skeeman ja osavaltion viestinvälittimen. Siihen asti kullakin yhtiöllä voi olla oma osoitteensa ja tokeninsa HTTPS:n yli (Hälytysyhtiöt & luvat (luku 91)).

Paikka

Yrityksen tai rakennuksen nimi, kompleksi tai kampus, rakennus, kerros, asunto tai huone (laji ja numero) sekä sisäänkäynti, portti tai kulkudetalji ovat erillisiä kenttiä. Ne ovat haettavissa, ja ne ratkaisevat, mitkä merkinnät pätevät. Muutos tässä ei koskaan muuta viranomaisen osoitteiden perustietoja.

Mitä tapahtuu seuraavaksi

Jokainen tällainen sijainti avaa location exception (sijaintipoikkeus) ja hälyttää vuorossa olevan esimiehen heti (katso Esimiehen tarkastus (luku 44)). Kun viranomainen myöhemmin vahvistaa tai yhdistää osoitteen, tehtävä linkittyy perustietopisteeseen; se, mitä syötettiin ja mitä yksiköille näytettiin, jää kirjaan.

Luku 39

Kohde- ja turvallisuusmerkinnät

Verkkokäyttöliittymässä: /admin/flags

Merkintä (flag) on viranomaisen varoitus vahvistetusta osoitteesta tai henkilöstä: premise, location, hazard, officer safety, medical, business, keyholder tai maintenance, unsafe structure, domestic violence, dangerous animal, polling place, evacuation location (viranomainen voi nimetä uudelleen, lisätä tai poistaa luokkia käytöstä).

  • Laajuus: kukin merkintä asetetaan kapeimpaan oikeaan paikkaan: koko kiinteistöön, kompleksiin, nimettyyn yritykseen, rakennukseen, kerrokseen tai yhteen asuntoon. Yhden asunnon varoitusta ei koskaan näytetä muulle kompleksille.
  • Milloin se näkyy: heti kun hätäkeskuspäivystäjä vahvistaa osoitteen, ennen puhelun lähettämistä, rivinä joka välilehdellä, sitten päivystäjän tehtävässä ja mobiilipäätteellä. Kriittiset ja korkeat merkinnät ovat tällä rivillä; Hazards-välilehti luettelee jokaisen ja sen, mitä yksiköiden tulisi tehdä.
  • Mitä se kertoo: vakavuus ja luokka sanoin, otsikko, mikä huolenaihe on ja miksi, ja mitä yksiköiden tulisi tehdä. Avaa se nähdäksesi lähteen ja yksityiskohdat.
  • Rajoitetut luokat (medical, domestic violence, officer safety, keyholder): ne, joille viranomainen ei anna lupaa, näkevät varoituksen ja mitä tehdä, eivät syytä eivätkä lähdettä. Yksityiskohdan avaaminen kirjataan; hylätty pyyntö myös.
  • Versiot: merkinnän muuttaminen, uusiminen, poistaminen käytöstä tai palauttaminen luo uuden version. Kukin tehtävä säilyttää sen version, jonka se näytti, joten myöhemmät muutokset eivät koskaan kirjoita uudelleen sitä, mitä päivystäjät näkivät.
  • Vahvistamattomat sijainnit eivät koskaan saa pysyvää merkintää. Vahvistamattoman pisteen lähellä olevat merkinnät näkyvät vain muodossa POSSIBLE MATCH NEARBY (mahdollinen osuma lähellä); sen sijaan voidaan säilyttää vain tehtävälle tarkoitettu muistiinpano.
  • Kuka saa: kukin luokka määrittää, mitkä tehtävät sen luovat, hyväksyvät ja näkevät. Muut (ja harjoittelijat) ehdottavat; esimies hyväksyy tai hylkää. Kaksi saman luokan merkintää samalla laajuudella näytetään päätöstä varten sen sijaan, että toinen korvaisi toisen.

Lisää merkintä puhelun kirjauksesta (Hazards, Add a flag or a note for this place) tai täältä Administa, jossa ehdotetut merkinnät odottavat hyväksyntää. Avaa Flags (luku 39)

Luku 40

Henkilöt ja ajoneuvot

Henkilöt, ylhäältä alas

Rooli (useampi kuin yksi, kun se sopii), sitten First, Middle ja Last name erillisissä kentissä, pääte ja aliakset; missä henkilö on (tehtävä, muualla rakennuksineen, kerroksineen ja yksikköineen, tuntematon, paikasta toiseen liikkuva); puhelinnumerot (useita, tyyppeineen, alanumeroineen, lähteineen ja onko vahvistettu); kuvaus yhtenä (sukupuoli, rotu, etnisyys, pituus, paino, ruumiinrakenne, hiukset, silmät, vaatetus, arvet, merkit ja tatuoinnit, hyväksytyin koodein); sitten tunnisteet: Social Security -numero, ajokortti ja osavaltio, muu tunniste, syntymäaika ja, erikseen, ilmoitettu arvioitu ikä. Ikä lasketaan syntymäajasta. Muistiinpanot viimeisenä.

Officer-safety concern avaa pakollisen osion: lyhyt hälytysotsikko, mitä tapahtui ja miksi se on huolenaihe, aseet tai uhka, mitä yksiköiden tulisi tehdä, lähde ja sen luotettavuus. Sitä ei voi tallentaa ilman niitä. Valitse This incident only tai Propose a permanent warning: ehdotus menee viranomaisen tarkastukseen henkilömerkintänä. Kaikkialla hälytys näkyy muodossa OFFICER SAFETY: ja sen otsikko, ja avautuu syyhyn, lähteeseen ja ohjeeseen.

Search kutakin nimen osaa erikseen (etunimi John löytää jokaisen Johnin), syntymäajalla, arvioidulla iällä, puhelimella, osoitteella, ajokortilla, sukupuolella, rodulla, liitetyllä rekisterikilvellä, kuulostaa kuin- ja osittaishaulla. Possible same person näkyy nimeä kirjoittaessa eikä koskaan estä tallentamista.

Social Security- ja ajokorttinumerot näkyvät peitettyinä jokaisella jaetulla näytöllä. Open (recorded) näyttää ne viranomaisen sallimille tehtäville, tarkoitus kirjattuna.

Ajoneuvot, ylhäältä alas

Roolit (epäilty, uhri, varastettu, löydetty, liikennepysäytys, todiste, hinattu ja muita), rekisterikilpi viranomaisen osavaltio ensin, kilven tyyppi ja kunto (väliaikainen, osittainen, lukukelvoton, ei lainkaan, useita), VIN (tarkistetaan kirjoittaessa; osittainen VIN säilytetään muistiinpanon kera), sitten Run DMV tai Run NCIC, kun kilpi ja osavaltio tai täysi VIN on syötetty. Vastaus liitetään kyseiseen ajoneuvoon aikoineen, kuka ajon teki ja kuka pyysi. Viralliset arvot näkyvät ilmoitetun vieressä, ja ero nimetään; mitään ilmoitettua ei korvata. Uusi ajo on uusi versio.

Liitä kuljettajat, omistajat, vuokralaiset, matkustajat ja ajoneuvossa olleet puhelun henkilöihin; kukin henkilö näyttää myös ajoneuvonsa. Mahdollinen varastettu- tai etsintäosuma näkyy muodossa POSSIBLE HIT: not confirmed (mahdollinen osuma: ei vahvistettu), kunnes osumavahvistukseen on vastattu (katso NCIC- ja osavaltiopyynnöt (luku 41)).

Tow ajoneuvolla avaa kyseisen ajoneuvon hinauksen: seuraava yhtiö viranomaisen vuorolistalla ylinnä puhelimineen ja viime vuoroineen, sitten Accepted, Declined (syyn kera) tai No answer, kunkin vaiheen aika, kuljettaja, auto, varastointipaikka, impound-numero, pidätys ja luovutusrajoitus. Kieltäytyvä yhtiö menettää vuoronsa, ja seuraavaa tarjotaan. Kukin ajoneuvo säilyttää omat hinauksensa. Komentorivillä SE.AD6 ja sitten F10 avaa saman hinauksen AD6:lle valitulla tehtävällä ja kysyy, mikä ajoneuvo.

Luku 41

NCIC- ja osavaltiopyynnöt

Verkkokäyttöliittymässä: /requests

Yksi työjono jokaiselle DMV-, VCIC-, NCIC-, Nlets- ja toisen osavaltion tapahtumalle, joka koskee henkilöitä, ajoneuvoja, kilpiä, VIN-numeroita, esineitä, aseita, veneitä ja arvopapereita.

  • Jono näyttää vain metatiedot: pyyntötyypin, tehtävän, tietueen, kuka pyysi (yksikkö tai poliisi), milloin, vastuullisen päivystäjän, kuka lähetti sen ja minne (ORI), kuka vastaanotti vastauksen ja milloin, tilan ja ratkaisun. Itse vastaus avataan henkilön tai ajoneuvon tietueesta niille, joilla on lupa.
  • Tilat: New, Assigned, Sent, Awaiting return, Possible hit, Hit confirmation sent, Confirmed valid, Not valid, Will not extradite, Extradition limited, Pending further information, No record, Error, Cancelled, Reassigned, Complete (viranomainen voi nimetä ne uudelleen).
  • Nearly due (pian erääntyvä) ja OVERDUE (erääntynyt) näkyvät sanoin. Erääntynyt pyyntö ilmoittaa omistajalleen ja vuorossa olevalle esimiehelle kerran.

Osumavahvistus

Tarkasta henkilö- tai ajoneuvotietueesta (tai jonosta): tietue ja vastaus, jotka vahvistetaan, pyytäjä, syöttäneen viranomaisen ORI, menetelmä, urgent (10 minuuttia) tai routine (yksi tunti), kuten NCIC-käytäntö määrää, ja muistiinpanot. Kirjaa vastaus sen kanssa, kuka vastasi ja milloin: Confirmed valid, Not valid, Will not extradite, Extradition limited, Cancelled tai Pending further information, muistiinpanoineen luovutusrajoituksista, noutosäteestä, varovaisuudesta ja viitenumeroista. Vahvistuksen lähettäminen ei koskaan tee osumasta vahvistettua.

Vuoronvaihdossa

Kullakin avoimella pyynnöllä on yksi vastuullinen päivystäjä. Uloskirjautuminen estetään, kun omistat avoimia pyyntöjä: saata kukin loppuun, tai luovuta se toiselle päivystäjälle (joka ottaa sen vastaan) tai jonoon, muistiinpanon kera siitä, mikä on kesken. Koko omistajien ketju jää pyyntöön. Avaa pyynnöt (luku 41)

Esittelyssä kytkin on koulutussimulaattori: kilpi tai nimi, joka alkaa sanalla TEST, vastaa mahdollisena osumana, ja jokainen vastaus on merkitty simuloiduksi.

Luku 44

Esimiehen tarkastus

Verkkokäyttöliittymässä: /supervisor

Yksi näyttö esimiehen tarkastustyölle, välilehdissä. Kukin kohta säilyy, kunnes se on käsitelty.

Sijaintipoikkeukset

Jokainen pakotettu, arvioitu tai muuten vahvistamaton tehtävän sijainti hälyttää vuorossa olevan esimiehen heti (kiireellinen tai korkea viesti) ja odottaa tässä sen kanssa, mitä kirjoitettiin, hyväksytyn sijainnin ja karttapisteen, lähteen ja luottamuksen, lähimmät vahvistetut vaihtoehdot, soittajan koordinaatit, kuka syötti sen millä työpisteellä, syyn, yksiköt ja tehtävän tilan. Tehtävän avaaminen ei poista sitä. Acknowledge se, ja vastaa sitten kahteen erilliseen kysymykseen:

  1. Was the best available location information used? Kyllä, tai ei sen kera, mikä oli parempaa.
  2. Does the agency's address source or workflow need follow-up? Ei jatkotoimia, Submit address or GIS update, Correct or merge master record, Refer to another jurisdiction, Training or workflow review, System defect tai Pending follow-up, kukin omistajineen ja eräpäivineen, sitten done.

Osoitejono vie sen läpi tilojen New, Under review, Verified, Rejected tai Merged; vahvistaminen tai yhdistäminen linkittää tehtävän perusosoitteeseen (aktiivisen tehtävän päivystäjät ja yksiköt näkevät muutoksen) ja säilyttää sen, mitä syötettiin.

Kriittiset tehtävät

Viranomainen määrää, mitkä puhelutyypit, modifierit, kiireellisyydet, tapahtumat (yksikön hätätilanne) ja ilmaukset tekevät tehtävästä kriittisen (Admin › Critical incidents). Laukaisin hälyttää esimiehen ja avaa yhden tarkastuksen tehtävää kohden; useammat laukaisimet lisätään siihen. Esimies voi myös merkitä tehtävän kriittiseksi tai poistaa merkinnän, syyn kera; laukaisimet jäävät kirjaan.

Open full review kokoaa sen pyydettäessä: lähdeluettelon, henkilöt ja heidän tehtävänsä, puhelunkäsittelyn virstanpylväät sen tapahtuman kera, josta kukin on peräisin, kunkin yksikön ajat, merkityn radioliikenteen (konemerkinnät, vain apu), pyynnöt (metatiedot), QA-matriisin ja todisteiden rajoitukset. Kukin laskettu aika näyttää tapahtumat, joiden väliltä se mitattiin. Vastaa kuhunkin QA-mittariin Met, Not met, Not applicable, Unable to determine tai Needs follow-up kommentin ja sen todisteen kera, johon se nojaa. Valitse todisteiden katkaisupiste ja Issue versio (sen tiiviste säilytetään); myöhempi todiste luo uuden version. Records-request copy ja Accreditation copy soveltavat viranomaisen luovutussääntöjä erilliseen kopioon redigointilokin kera; itse tarkastusta ei koskaan muuteta. Offer support ja Open after-action kirjaavat vain toiminnalliset toimet; mitään kliinistä tai hyvinvointiin liittyvää yksityiskohtaa ei mene CADiin.

Ilmaushälytykset

Määritetyt ilmaukset, jotka kuullaan puhelu- tai radiolitteroinneissa tai kirjoitetaan narrativeen, hälyttävät esimiehen kontekstin, lähteen, kanavan, puhujan ja ajan kera. Kielletty ilmaus ("no shots fired") merkitään tarkastusta varten NEGATED (kielletty), ja matalan luottamuksen ilmaus UNCERTAIN (epävarma). Ratkaise kukin: Reviewed no action, Critical incident opened, Linked to existing review, False positive tai Follow-up required.

Shift Intelligence

Raportti kullekin toiminnalliselle jaksolle (Admin › Call entry rules asettaa jaksot), koottu kirjauksista: merkittävät ja avoimet tehtävät, sijaintipoikkeukset ja niiden tarkastus, kriittiset tehtävät, uudet ja kriittiset merkinnät, BOLOt ja kiireelliset viestit, vajaamiehitetyt yksiköt, erääntyneet tilatarkistukset, avoimet pyynnöt ja velaksi jäänyt jatkoselvitys, kukin lähteineen, aikoineen, tiloineen, omistajineen, eräpäivineen ja seuraavine toimineen. Aja se nykyiselle jaksolle, aiemmalle tai mukautetulle välille. Lisää esimiehen yhteenveto ja luovutusmuistiinpanot (pidetty erillään tosiasioista) ja Finalize; myöhemmät muutokset ovat lisäyksiä syyn kera. Vuoroon tuleva esimies acknowledges sen ja hyväksyy tai siirtää uudelleen kunkin avoimen jatkotoimen, joka kannetaan eteenpäin, yksi kohta lähdettä kohden, kunnes valmis. Rajoitettu yksityiskohta näytetään vain niille, joilla on lupa.

Tietojenluovutussäännöt

Verkkokäyttöliittymässä: /admin/disclosure

Disclosure rules ovat viranomaisen oikeudellisesti tarkastetut säännöt asiakirjapyynnöille (FOIA). Mitään ei ole kovakoodattu salassa pidettäväksi; järjestelmä ehdottaa, ihmiset päättävät, ja lakimiehesi tarkastaa jokaisen säännön ennen kuin se otetaan käyttöön.

Säännöllä on tunnus, nimi, lainkäyttöalue ja tietuetyypit, ja se osuu seuraavilla:

  • Category: tietueen nimetty kategoria.
  • Words: mikä tahansa pilkuin erotetusta listasta.
  • Pattern: Go-säännöllinen lauseke.

Legal basis vaaditaan, selityksen, valinnaisen voimassaoloikkunan ja käyttöönkytkimen kera. Sääntö pysyy pois käytöstä, kunnes lakimies on tarkastanut sen.

  • Add the sample rules (disabled) lataa esimerkkejä; ne ovat esimerkkejä, eivät oikeudellista neuvontaa.
  • Try it liittää tietueen tekstin ja näyttää sen ehdotetut kohdat korostettuina — keltainen missä varmuus on "review", ruusunpunainen missä se on "high" — ja listan kustakin tekstinsä, sääntönsä, perustelunsa ja varmuutensa kera.

Luku 57

Litteroinnit ja mitä kuultiin

Kun puhelunkäsittely litteroi puheluita, kukin puhelu näyttää litterointinsa suorana, soittaja valkoisella ja hätäkeskuspäivystäjä sinisellä, sekä Heard on the call: siitä poimitut tiedot, jotta hätäkeskuspäivystäjä kirjoittaa vähemmän.

  • Mitä poimitaan: osoite, aseet, ajoneuvot, rekisterikilvet, suunta johon joku meni, montako henkilöä, vammat (ei hengitä, tajuton, vuotaa verta), vaarat (tuli, loukussa, kaasu, koira, sähköauto) ja soittajan nimi. Kiireelliset ovat punaisia ja tulevat ensin, ja näkyvät puhelulla jonossa.
  • Käyttö: osoitteella sijoittaa puhelun tehtävän sinne (karttahaku, tarkka kun kartta tuntee numeron; tarkista se kartalta). Ennen tehtävää se kopioi osoitteen.
  • Mistä litteroinnit tulevat: BitVoicen suora litterointi kun se lähettää sellaisen, sen litterointi tallennetusta puhelusta jälkikäteen, tai mikä tahansa puheentunnistusmoottori joka lähettää litterointiliitäntään (Liitännät (luku 78)).
  • Säännöt, ei malli, poimivat tiedot: samat sanat antavat aina samat tiedot, ja kukin näyttää sanat joista se tuli.
Litterointi on sitä mitä kone kuuli. Hätäkeskuspäivystäjän oma harkinta ja kysymykset ratkaisevat yhä.
Luku 58

Toista kieltä puhuvat soittajat

Toista kieltä puhuva soittaja käännetään rivi riviltä tekstityksessä, merkittynä kielellä (Spanish · translated); Show original näyttää, mitä sanottiin.

  • bitdispatcheriin sisäänrakennettu fraasisanakirja toimii offline-tilassa. Espanjaksi se kääntää hätätilanteiden sanat molempiin suuntiin; kun se osaa liian vähän rivin sanoista, se sanoo gist only (vain pääasia): hanki tulkki.
  • Kaksitoista muuta kieltä: arabia, kiina (mandariini), ranska, haitinkreoli, hindi, japani, korea, puola, portugali, venäjä, tagalog ja vietnam. Kieli tunnistetaan sen kirjoitusjärjestelmästä tai sanoista. Soittajan rivistä tulee gist (pääasia): löydetyt hätätilanteen sanat järjestyksessä, ja … muun osalta ("fire · my house · … · please hurry"). Puhelunkäsittelijän ready phrases (valmiit fraasit) sanotaan kullakin niistä; kirjoitettua englantia ei, koska fraasisanakirja ei keksi lausetta, jota sillä ei ole. Nämä fraasisanakirjat on kirjoitettu koneellisesti, eivätkä syntyperäiset puhujat ole tarkistaneet niitä.
  • Sano se soittajan kielellä: paina valmista fraasia (Help is on the way, Is the person breathing?, Get out of the house now…) tai, espanjaksi tai kielimallilla, kirjoita englanniksi; käännös näkyy kirjoittaessasi. Se säilytetään tekstityksessä, lähetetään tekstiviestinä, kun also text it (lähetä myös tekstinä) on valittuna (BitVoice), ja kaiutinpainike sanoo sen ääneen tällä konsolilla selaimen kyseisen kielen äänellä.
  • Kielimalli (valinnainen, Admin › Integrations) kääntää sen, mihin fraasisanakirja ei pysty, OpenAI-yhteensopivalla keskustelu-API:lla: omalla palvelimellasi tai viraston sopimuksen alainen palvelu. Soittajien sanomat lähetetään sille, joten se on pois päältä, kunnes ylläpitäjä ottaa sen käyttöön.

Luku 60

Sijaintilinkit: soittaja jakaa, missä hän on

Kun puhelu ei tuo käyttökelpoista sijaintia (matkapuhelimesta ohjattu lankapuhelu, soittaja joka ei tiedä missä on, huono solupaikannus), puhelun Send location link lähettää soittajalle linkin: tekstiviestinä BitVoicen kautta, kun puhelu voi ottaa vastaan tekstiviestin, tai näytettynä ääneen luettavaksi.

  • Soittaja avaa sen ja painaa Share my location (jaa sijaintini); puhelin pyytää lupaa siihen. Sen oma sijainti (GPS, muutama metri ulkona) tulee puheluun merkittynä *Shared by the caller (phone's location, by link)*, ja uudelleen soittajan liikkuessa, noin muutaman sekunnin välein sivun ollessa auki.
  • Puhelu näyttää linkin tilan; end it (lopeta se) pysäyttää sen. Soittaja voi painaa Stop sharing (lopeta jakaminen). Linkki kestää 30 minuuttia (Admin › Settings › Calls: location links) ja ottaa vastaan enintään 900 sijaintia.
  • Linkki sisältää pitkän satunnaisen salaisuuden; vain sen tiiviste säilytetään. Se avaa pienen sivun, jolla ei ole kirjautumista eikä mitään muuta.
  • Linkki käyttää Hakuryhmät (luku 84)-kohdan julkista osoitetta: soittajan puhelimen on voitava tavoittaa tämä palvelin sillä, varmenteella johon puhelin luottaa.

Ei-kiireelliset puhelut

Luku 63

Ei-kiireellinen vastaanotto

Verkkokäyttöliittymässä: /admin/intake

Ei-kiireellisellä linjalla oleva puhe- tai tekstibotti (BitVoicen tekoälyvastaanottovirkailija tai muu) voi ottaa ilmoituksia vastaan. Botti kantaa äänen; bitdispatcher päättää, mitä se kysyy.

  • Kysymykset: esitetään järjestyksessä, kukin vastaustyyppeineen (sanat, osoite, puhelinnumero, kyllä tai ei). *needed* (tarvitaan) kysyy vielä kerran, kun vastaus on tyhjä. Kyllä/ei-kysymys, joka on merkitty yes = hand over (kyllä = luovuta), siirtää soittajan henkilölle kyllä-vastauksella, tai kun vastaus on epäselvä. Avaimet where, phone ja name täyttävät ilmoituksen osoitteen (sijoitetaan kartalle, kun tallennettu kartta löytää sen tarkasti), takaisinsoiton ja soittajan.
  • Luovuttaminen: sillä hetkellä, kun soittaja sanoo jonkin hätäsanoista (oletuksena: emergency, hurt, bleeding, fire, gun, breaking in, right now… ja viraston kriittiset sanat), tai jotakin, minkä tekstityksen lukija merkitsee kiireelliseksi, botille kerrotaan sanoa luovutusrepliikki ja siirtää soittaja puhelunkäsittelijälle. Sana heti sanojen *no*, *not* tai *nobody* jälkeen ("nobody is hurt") ei lasketa.
  • Valmis ilmoitus on puhelu ei-kiireellisten luettelossa (luku 62), kaikkine vastauksineen, keskusteluineen ja ilmoitusnumeroineen, joka soittajalle kerrotaan. Sen perusteella ei lähetetä mitään; henkilö tekee siitä tehtävän tai sulkee sen. Luovutettu keskustelu on hätätilanteeksi merkitty puhelu, sanottuine asioineen.
  • Botin token: Make the token (luo token; näytetään kerran). Botti kutsuu POST /api/intake/sessions aloittaakseen ja POST /api/intake/sessions/<id> jokaisella soittajan sanomalla asialla; jokainen vastaus kertoo, mitä sanoa seuraavaksi ja luovutetaanko (docs/INTAKE.md).
  • Try it (kokeile sitä) ajaa tallennetun käsikirjoituksen keskustelussa, kuten soittaja tekisi, eikä tee ilmoitusta.
Luku 64

Ajoneuvon kolaridata

Ajoneuvon automaattinen kolari-ilmoitus saapuu puheluna merkinnällä CRASH DATA: ajoneuvo, delta-V (nopeuden muutos kolarissa), iskun suunta, kattoonmeno, turvatyynyt, matkustajat ja vyöt, sekä sen käyttövoima (sähkö, hybridi).

  • Injury risk on korkea delta-V:lle 40 km/h (25 mph) tai enemmän, kattoonmenolle, tai 20 km/h ilman vyötä, useilla iskuilla tai sivutörmäyksellä; keskitaso 20 km/h:lle tai mille tahansa turvatyynylle. Ehdotukset seuraavat: ALS, irrotus, lääkärihelikopteri, useampi kuin yksi ambulanssi, ja sähköautolle sana palomiehistöille.
  • Se on nyrkkisääntö kenttätriage-kriteereistä auttamaan vasteen valinnassa, ei diagnoosi. Muuta kynnysarvot Admin › Settings (luku 110) -osiossa.
  • Kolari-ilmoitukset saapuvat bitdispatcheriin kolariliitännän (Liitännät (luku 78)) kautta.

Luku 66

Admin: Drones

Verkkokäyttöliittymässä: /admin/drones
Tämä luku muuttui käännöksen jälkeen ja näytetään englanniksi, kunnes käännös on päivitetty.

Drones bitdispatcher flies itself, over MAVLink, the protocol of the PX4 and ArduPilot autopilots. Each drone has:

  • MAVLink link: udp-listen:0.0.0.0:14550, udp:host:port, tcp:host:port or serial:/dev/ttyUSB0:57600, and the autopilot's system id (0 takes the first one heard).
  • Signing key: 64 hex digits for MAVLink 2 signing. Turn it on: without it anyone who can reach the link can command the drone. A drone signing with another key is ignored.
  • Camera: an RTSP address for H.264 video. The password is masked here and never logged.
  • Height (10 to 120 m) and the lowest battery for a launch.
  • Needs pilot approval and the pilots: listed pilots approve a launch; with none listed, supervisors do. A launch rule always waits for a person.
  • Record video: while the drone is on an incident its video is kept with the incident, with its size and SHA-256 written to the ledger every 10 seconds. A recording that no longer matches is not served.

On an incident, Send a drone picks the nearest ready drone. Dispatchers can press Hold or Return home; the pilot's own controller can take over at any time. Training boards never fly real drones. Check Part 107, Remote ID and your state's drone laws before flying.

Tested with the bundled simulator (bin/dronesim) only, not yet a real drone. Details in docs/DRONES.md. Open Drones (luku 66)

Luku 72

Harjoitukset, injektit ja esivalmistelu

Harjoitus on yksi harjoitustaulu kaikille, jotka siihen liittyvät: valitse Training sisäänkirjautuessa ja kirjoita harjoituksen nimi (mikä tahansa nimi; ensimmäinen liittyjä luo sen). Yksin harjoitellessa jätä nimi tyhjäksi.

Kouluttaja (esimies tai järjestelmänvalvoja) painaa Inject: uusi soittaja (missä, kuka ja mitä he sanovat harjoituksen edetessä), soittaja joka kertoo lisää tai liikkuu, yksikkö joka menee pois palveluksesta, hätänappi tai yksikkö radiossa. Timeline lataa jokaisen tapahtuman purkukeskustelua varten, ja kun harjoitus päättyy, sen aikajana säilytetään (Esimiehet: /api/exercises).

Esivalmistelu. Järjestelmänvalvoja, joka on kirjautunut sisään Training-tilassa, muuttaa tehtävätyyppejä, yksiköitä, asemia, vastesuunnitelmia, ohjeistusta tai palveluja harjoitustaululla, kokeilee niitä siellä, ja avaa sitten Staged changes: se listaa mikä eroaa live-taulusta; valitse osat, kerro miksi, ja Publish. Kun *Change configuration only through staging* on päällä (Settings), näitä muutoksia ei voi tehdä live-taululla suoraan.

Harjoitustaulu ei ole live-taulun varmuuskopio. Jatkuvuussivusto on erillinen, testattu järjestely: katso Useita sivustoja (luku 115).

Luku 74

Katkoksen läpi työskentely

Kukin konsoli säilyttää viimeisen taulun joka sillä oli. Kun palvelinta ei saada yhteyteen, keltainen palkki kertoo siitä ja konsoli näyttää sen taulun, sellaisena kuin se oli, aikoineen. Katkoksen aikana uudelleenladattu konsoli avautuu silti.

  • Offline-loki: uudet tehtävät, muistiinpanot ja yksiköiden tilat säilytetään tässä selaimessa, järjestyksessä.
  • Kun palvelin on takaisin, palkki tarjoaa Send them now: kukin menee sisään merkittynä "entered offline at 14:02 by jlee"; mikä tahansa minkä palvelin epää, jää, perusteluineen.
  • Palvelimelle joka ei koskaan katoa, aja bitdispatcher kahdella sivustolla (Useita sivustoja (luku 115)): kumpikin jatkaa toimintaa kun toinen on katkaistu.
  • Kun internet, palvelimen sijaan, on poissa, tai keskuksen on jätettävä rakennuksensa, katso Jatkuvuus (luku 75).
Luku 75

Jatkuvuus: katkokset ja varakeskus

Verkkokäyttöliittymässä: /continuity

Jatkuvuus-sivu (pelastusrengas-painike tilarivissä, tai siellä oleva merkki kun jokin on vialla) on se, mikä pitää keskuksen toiminnassa kun yhteys tai rakennus menetetään.

Kun internet katoaa

bitdispatcher toimii keskuksen omalla palvelimella, joten internetin menettäminen ei pysäytä hälyttämistä. Puhelunsyöttö, tehtävät, yksiköt, tallennettu katukartta, reititys ja osoitteet, tapahtumaloki ja tulostus jatkavat toimintaansa.

  • Mikä odottaa internetiä: online-karttaruudut, Street View ja tallentamattomat ilmakuvat, liikenne, karttapäivitykset, naapurikeskukset ja ylivuoto, NERIS, PSC PIP, sekä BitVoice tai hakulaitejärjestelmä kun ne tavoitetaan internetin yli.
  • bitdispatcher tarkistaa osoitteet jotka ylläpitäjä asettaa (Admin › Jatkuvuus (luku 116)), BitVoicen, muut sivustot ja kunkin ylivuodon naapurin. Kun yksikään internet-tarkistus ei vastaa, jokainen konsoli näyttää Internet down punaisella ja esimiehet saavat viestin; toinen yhteyden katkeaminen näkyy keltaisena merkkinä.
  • Kukin yhteyden katkeaminen ja palaaminen on tapahtumalokissa; sivu listaa yhteydet ja katkokset.

Varakeskukseen siirtyminen

Kun keskuksen on jätettävä rakennuksensa, henkilöstö siirtyy varakeskukseen: toiseen bitdispatcher-sivustoon jonka piirikunta omistaa tai ajaa pilvessä (Useita sivustoja (luku 115)). Se pitää jo hallussaan jokaisen tietueen, joten työ jatkuu siitä mihin se jäi.

  1. Varakeskuksessa esimies painaa We are working from the backup site, muistiinpanon kera. Jokainen konsoli jokaisella sivustolla näyttää At backup site, ja jokainen vuorossa oleva saa viestin.
  2. Kohdassa Admin › Jatkuvuus asetettu tarkistuslista kuitataan sitä mukaa kun se tehdään (911:n uudelleenreititys, radion ohjausasemat, kentälle kertominen); kukin kuittaus on tapahtumalokissa.
  3. Kotona We are back in our building päättää sen.
911-puhelut saapuvat varakeskukseen vain kun puhelinverkko lähettää ne sinne: 911-viranomaisen vaihtoehtoinen reititys, tai BitVoicen reititys NG911:ssä. bitdispatcher ei voi siirtää puheluita itse.

Jatkuvuuspaketti

Open to print antaa sivun avoimista tehtävistä (soittajien nimineen ja takaisinsoittonumeroineen), jokaisen yksikön ja sen tilan, tarkistuslistan, yhteystiedot ja tyhjät lokirivit, paperilla työskentelyä varten jos CAD:iin ei saada lainkaan yhteyttä. Se voidaan kirjoittaa aikataulun mukaan kansioihin jotka ylläpitäjä asettaa: jaettu asema tai toisella koneella oleva USB-levy säilyttää tuoreen kopion jos tämä palvelin menetetään. Käsittele tulostettuja kopioita tietueina.

Luku 76

Ylivuoto naapurikeskukseen

Verkkokäyttöliittymässä: /overflow

Kun keskus on ylikuormitettu, tai poissa rakennuksestaan, naapurikeskus joka sekin ajaa bitdispatcheria voi ottaa sen puhelut; ja tämä keskus voi ottaa heidän. Se asetetaan kullekin naapurille kohdassa Admin › Jatkuvuus (luku 116), sen jälkeen kun molemmat keskukset sopivat siitä kirjallisesti.

Avun pyytäminen

  1. Ylivuoto-sivulla esimies painaa Ask (neighbour) to take our calls, kertoo miksi ja kuinka pitkäksi aikaa (4 tuntia ellei toisin asetettu).
  2. Naapurin esimies hyväksyy tai kieltäytyy; naapuri jonka asetukset hyväksyvät omin päin aloittaa heti. Molempien keskusten tilarivit näyttävät sen: *(neighbour) is taking our calls*.
  3. Kukin puhelu jonka he ottavat, muuttuu täällä tehtäväksi, numeroidemme ja puhelutyyppiemme alla, merkittynä Taken for us by (neighbour) heidän puhelunkäsittelijänsä nimen kera. Lähettäjämme lähettävät yksikkömme, ellemme anna naapurin myös jakaa niitä.
  4. Esimies kummassa tahansa keskuksessa painaa End kun se on ohi.

Puheluiden ottaminen naapurin puolesta

Sillä aikaa kun se kestää, Ylivuoto-sivu näyttää Take a call for (neighbour): sijainnin, heidän puhelutyyppinsä, soittajan, takaisinsoittonumeron ja mitä tapahtui. Send luo tehtävän heidän CAD:iinsa ja näyttää sen numeron.

  • Mitä puhelulle tapahtuu, palaa takaisin: sen tila, siinä olevat yksiköt, niiden muistiinpanot ja sulkeminen. Täällä lisätyt muistiinpanot menevät heille.
  • Jos he antavat meidän, Their units listaa heidän käytettävissä olevat yksikkönsä jaettaviksi.
  • Jos heidän CAD:iinsa ei saada yhteyttä, puhelu säilytetään täällä ja lähetetään uudelleen joka 20 sekunti; kerro heille radiolla tai puhelimella jos se on kiireellinen.

Mikä ylittää

Vain puhelut jotka naapuri ottaa, ja mitä niille tapahtuu: ei muita tehtäviä, ei tietueita, ei henkilöhistoriaa, ei NCIC-vastauksia. Jokainen pyyntö, vastaus, puhelu, muistiinpano ja jako on molempien keskusten tapahtumalokeissa.

911-puhelut itse saapuvat naapurille puhelinverkon vaihtoehtoisella reitityksellä, jonka 911-viranomainen asettaa, tai BitVoicen reitityksellä NG911:ssä. Ylivuoto kantaa työn, ei puheluita.
Luku 77

Linjahyökkäykset (TDoS)

Puhelinpalvelunesto täyttää linjat niin, etteivät todelliset soittajat pääse läpi. bitdispatcher tarkkailee puheluita ja nostaa Possible telephony denial-of-service jokaisella konsolilla ja esimiestaululla kun:

  • paljon enemmän puheluita saapuu minuutissa kuin tavallisesti (viisi kertaa viime tunnin tahti, vähintään 12, tai Settingsissa asetettu määrä);
  • yksi numero soittaa viisi kertaa tai enemmän kymmenessä minuutissa (näkyy nimellä ×5 puheluissaan);
  • kahdeksan tai enemmän hiljaista tai hyvin lyhyttä puhelua saapuu viidessä minuutissa.

Esimies kuittaa sen; se poistuu kymmenen hiljaisen minuutin jälkeen. Jatka vastaamista: todellinen hätätilanne voi olla niiden joukossa.

Luku 79

Hälytystasot: 2. ja 3. hälytykset

Työteliäs palo kasvaa yli ensimmäisen hälytyskorttinsa. Kullakin tehtävätyypillä voi olla lisähälytyksiä (Admin › Call types): 2. hälytys, 3., kukin lisäten yksiköitä siihen mitä tehtävä tarvitsee. Ensimmäinen hälytys on tehtävätyypin oma hälytyskortti.

Nostaminen

  • Tehtävällä Upgrade to 2nd alarm kertoo mitä se lisää (+2 engine, 1 ladder…); tai kirjoita ALARM (2ND, 3RD, ALARM 3 tasolle).
  • Nosto on prioriteettirivi aikajanalla, jonka jokainen päivystäjä ja miehistö näkee, lisäyksineen.
  • Suositus täyttää sitten suuremman hälytyskortin, laskien jo paikalla olevat yksiköt, ja REC (tai Ctrl Enter) lähettää lisäyksiköt. Hälytysryhmät ja asemahälytykset seuraavat hälytystä kuten tavallisesti.

Luku 80

Henkilöstö ja miehistöt

Verkkokäyttöliittymässä: /admin/personnel

Roster on viranomaisen henkilöt: numero, nimi, arvo, pätevyydet (paramedic, EMT, kuljettaja, poliisi…), kotiasema ja miten heitä hälytetään (puhelin tekstiviesteille, sähköposti, push-aihe). Lisää heidät yksitellen tai Import from CSV (sarakkeet: id, nimi, arvo, pätevyydet erotettuina merkillä ;, asema, puhelin, sähköposti, vapaaehtoinen).

Keitä on kyydissä

Millä tahansa yksiköllä (yksikön paneeli › Crew › change) tai miehistön omalta päätteeltä (Crew), valitse keitä ajaa sitä tänä vuorona. Jäsen on yhdellä yksiköllä kerrallaan: hänen laittaminen toiselle siirtää hänet. Tehtävän aikajana kirjaa miehistömuutokset sitä hoitavalla yksiköllä.

Mitä miehitys muuttaa

  • Minimum aboard (Admin › Settings › Unit types tai yksikkökohtaisesti Admin › Units): sen alittava yksikkö näytetään vajaamiehitettynä, suosituksen perusteluissa ja esimiehen poikkeuksissa.
  • What a capability needs (Admin › Settings › Crews): oletuksena ALS tarvitsee kyydissä paramedicin. Lääkintäyksikköä, jonka kirjatulla miehistöllä ei ole paramedicia, ei suositella ALS-riville (se on silti BLS ja kuljetus).
  • Yksikkö, jolla ei ole kirjattua miehistöä, otetaan miehitetyksi: viranomainen, joka ei pidä rostereita täällä, ei näe muutosta.
Päivystäjät näkevät rosterin ilman puhelinnumeroita ja sähköposteja; esimiehet näkevät ne.
Luku 81

Miehitys: kuka on vuorossa ja kullakin yksiköllä

Verkkokäyttöliittymässä: /staffing

Staffing (tilarivin henkilöpainike) näyttää kuka on vuorossa, missä, ja kuka todella miehittää kunkin yksikön. Pelkkä tunnus ei riitä: miehistö seuraa yksikköä tehtäviin, suosituksiin, historiaan ja raportteihin.

Vuorossa olevat henkilöt

Sign on työn lajin kera (tavallinen, ylityö, jatkovuoro, tilapäinen määräys ja missä, takaisinkutsu), vuoro, mihin asti ja käytettävyys (käytettävissä, osoitettu, ei käytettävissä, koulutus, oikeus, ruokailu, asematyö, hallinnollinen). Sign off vapauttaa henkilön mistä tahansa yksiköstä. Hae nimen, pätevyyden, viranomaisen, aseman, yksikön ja käytettävyyden mukaan.

Miehistöt

Edit crew nimeää yksikön henkilöt ja heidän roolinsa (kuljettaja, poliisi, palomies, lääkintämies, pari, ryhmänjohtaja tai viranomaisen omat). Yksikkötyyppi voi vaatia rooleja ja minimin (Admin › Settings › Unit types). Miehistö voi kirjautua itse sisään päätteeltä; viranomainen päättää yksikkötyypeittäin onko se sallittua, tarvitseeko se esimiehen hyväksynnän (Sign-ons waiting) vai onko se vain hälytyskeskukselle.

  • Yksi henkilö on yhdellä aktiivisella yksiköllä kerrallaan. Hänen laittaminen toiselle kysyy: move them (vapautus, vaihto) tai secondary assignment perusteluineen.
  • Kullakin muutoksella on perustelu ja effective-aika, säilytettynä sen vieressä milloin se kirjattiin.
  • Vajaaksi jätetty yksikkö (minimin alle, rooli tyhjänä) on limited tai laitetaan pois palveluksesta, kuten viranomainen määrää, ellei esimies kirjaa override-ohitusta perusteluineen.
  • Katkennut yhteys ei kirjaa ketään ulos.

Tehtävillä ja myöhemmin

Kun yksikkö osoitetaan, tehtävä säilyttää keitä oli kyydissä ja mihin he olivat pätevöityneitä sillä hetkellä; myöhemmät muutokset eivät koskaan kirjoita sitä uudelleen, ja tehtävän aikaiset muutokset (kuka liittyi, kuka lähti, roolit) ovat sen aikajanalla. Esimies voi korjata miehistötietueen perusteluineen: alkuperäinen pysyy korjauksen vieressä, kirjaus- ja voimaantuloaikoineen. Unit recall ja raportit näyttävät henkilöt tunnuksen lisäksi.

Esimiehet näkevät myös saved crews vuoronvaihtoa varten yhdessä vaiheessa (kukin henkilö ja aika yhä kirjattuna) ja coverage: minimin pätevistä henkilöistä jotka viranomainen haluaa vuoroon, aukot, vanhenevat pätevyydet ja kunkin yksikön kyvykkyys (esimiesnäkymä jota viranomainen hallitsee).

Luku 82

Pätevyydet, erikoisryhmät ja valtuutukset

Verkkokäyttöliittymässä: /admin/qualifications

Kukin viranomainen pitää valvottua taitotiedostoa (Admin › Qualifications & teams; esimiehet).

  • Qualifications: erikoisryhmät (Swift Water, HazMat, Technical Rescue, Dive, K-9, SWAT, UAS), erikoisalat (todisteteknikko, palotutkija, kriisineuvottelija, taktinen päivystäjä), koulutusroolit (CTO, FTO, kouluttaja, arvioija) ja valtuutukset (EMT, paramedic…), kukin tasoineen, omistava viranomainen, kuinka monta kuukautta se kestää, milloin uusinta erääntyy, esivaatimukset, onko se verified-vahvistettava ennen kuin se lasketaan, ja asiakirjat jotka se tarvitsee.
  • Henkilön valtuutukset: taso, tila (harjoittelija, pätevä, kouluttaja, arvioija, rajoitettu, tilapäisesti ei käytettävissä, pidätetty, vanhentunut), myöntäjä, päivät, rajoitukset ja liitetyt todistukset. Esimies merkitsee yhden verified; vahvistamaton itse kirjattu ei koskaan laske missä vahvistus vaaditaan. Jokainen muutos säilytetään.
  • Equivalencies: toisen viranomaisen pätevyys hyväksyttynä meidän pätevyydeksemme, laajuutensa ja vanhenemisensa kera, keskinäistä apua varten; henkilön omaa tietuetta ei koskaan yhdistetä tai korvata.
  • Reminders: esimiehille kerrotaan kerran kun valtuutuksen uusinta erääntyy ja kun se vanhenee.

Live-kyvykkyys

Yksikön kyvykkyys tulee kalustosta ja pätevästi pätevöityneistä henkilöistä nyt kyydissä: HazMat-yksikkö ilman vaadittuja teknikoitaan ei ole HazMat-kyvykäs, ja näyttää LIMITED perusteluineen (mitä kukin kyvykkyys miehistöltä vaatii asetetaan Personnel-osiossa). Suositus käyttää live-kyvykkyyttä; viranomainen päättää onko vajaan yksikön lähettäminen vain varoitettu, tarvitseeko se esimiehen ohituksen vai onko se estetty. Päivystäjät näkevät kyvykkyyden ja pätevyyksien nimet; valtuutustiedot ovat esimiehille ja henkilölle.

Luku 83

Palopaikan miehistöseuranta: miehistötarkastukset (PAR)

Työteliäässä palossa palopäällikkö tekee miehistötarkastuksen (PAR) jokaisesta paikalla olevasta miehistöstä asetetuin väliajoin, ja hälytyskeskus pitää kelloa.

  • Tehtävätyyppi, joka on merkitty Fire-ground accountability (Admin › Call types), käynnistää kellon kun ensimmäinen yksikkö saapuu paikalle; Start roll calls käynnistää sen millä tahansa palotehtävällä.
  • Tehtävä näyttää ajan kellon käynnistymisestä ja milloin seuraava PAR erääntyy; se muuttuu keltaiseksi kun myöhässä, ja esimiehen taulu listaa sen.
  • All accounted for (tai PAR) kirjaa miehistötarkastuksen jokaisesta paikalla olevasta miehistöstä. Miehistö joka ei vastannut: napsauta sitä, sitten Report … missing (tai PAR MISSING E3). Se on punainen, vilkkuva rivi tehtävällä ja kiireellinen poikkeus esimiehelle kunnes E3 found (PAR FOUND E3).
  • Benchmarks joita päällikkö raportoi (primary search complete, fire under control, loss stopped…) ovat yksi napsautus kukin, tai BM UC, ajan kera tehtävän alkamisesta.
  • Kello pysähtyy kun tehtävä sulkeutuu; sitä ei voi pysäyttää miehistön ollessa kateissa.
Väli on 20 minuuttia ellei muutettu Admin › Settings -osiossa tai tehtävätyypillä.
Luku 84

Vastaajien hälyttäminen

Verkkokäyttöliittymässä: /admin/paging

Vapaaehtoisia ja vapaalla olevia palomiehiä ja EMT-henkilöitä kutsutaan page-hälytyksellä. Paging group kertoo, keitä hälytetään yhdessä ja miten:

  • Members rosterista (Henkilöstö (luku 80)).
  • Gateways: miten hälytykset lähtevät, järjestelmänvalvojan asettamana Admin › Integrations › Paging -osiossa: tekstiviesti Twiliolla, sähköposti, push puhelimiin ntfyllä, webhook, tai IamResponding ja Active911 (molemmat ottavat hälytyksen sähköpostitse dokumentoiduissa muodoissaan).
  • Automatic: hälytä ryhmä kun yksi sen yksiköistä tai asemista hälytetään, tai kun jonkin sen tehtävätyypin tehtävä saa yksiköitä. Kukin ryhmä hälytetään kerran tehtävää kohden sääntönsä mukaan.

Hälytys

Hälytyksen aihe on tehtävätyyppi ja osoite, teksti tehtävän yhteenveto ja yksiköt. Kukin henkilö saa linkin vastatakseen: Responding to the station, Going straight to the scene tai Not available, sen kera milloin he odottavat saapuvansa. Ei sisäänkirjautumista: linkki on avain, ja toimii vain kyseiselle henkilölle ja kyseiselle hälytykselle.

Tehtävällä Responders näyttää kuinka monta hälytettiin ja vastasi, kunkin henkilön vastauksen ja minuutit matkaa; Page hälyttää lisää ryhmiä. PAGE <group> / text tekee sen komentoriviltä. Hälytys, johon kukaan ei ole vastannut viiden minuutin jälkeen, on esimiehen poikkeuksissa; epäonnistuneet toimitukset ovat aikajanalla.

Aseta address responders open (Admin › Integrations › Paging) osoitteeseen, josta puhelimet tavoittavat tämän palvelimen; ilman sitä hälytykset lähtevät ilman vastauslinkkiä. Testattu Twilion, ntfyn, sähköpostin ja webhookin sijaisia vasten; ei IamRespondingin tai Active911:n sertifioima.

Yhteystietohakemisto ja päivystyslistat

Luku 95

Yleisön varoittaminen

Esimiehet varoittavat yleisöä konsolilta: shelter in place, evacuate, poliisitoiminta, vaarallinen vuoto, kadonnut lapsi, 911 alhaalla. Paina tilarivin megaphone-painiketta tai Alert the public tehtävällä.

Hälytyksen kirjoittaminen

  • Real alert, Exercise tai Test: harjoitus tai testi merkitään sellaiseksi kaikkialla minne se menee. Tarkista tämä ensin.
  • Kind of alert: SAME-tapahtumakoodi (SPW shelter in place, EVI evacuation, LEW law enforcement, HMW hazardous materials, CAE child abduction, TOE 911 outage…). Yhden valitseminen täyttää sanamuodon, englanniksi ja espanjaksi, lähtökohdaksi.
  • Headline, what is happening ja what to do.
  • Phone alert: mitä puhelimet näyttävät ensin (Wireless Emergency Alerts, 90 merkkiä) ja mitä tekstiviestit ja push-ilmoitukset sanovat; laskuri muuttuu punaiseksi rajan jälkeen. Longer phone alert (360) on valinnainen.
  • Also in Spanish lisää espanjankielisen version; listoilla olevat jotka valitsivat espanjan saavat sen.
  • Where: tehtävän ympärillä (neljännesmaili kahteen mailiin), kartalle piirretty alue (Admin › Geofences) tai everyone lainkäyttöalueella (sen piirikuntakoodit).
  • Expires after yhdestä 24 tuntiin.
  • Send to valitut tilaajalistat ja CAP-järjestelmät (sireenit, hälytysohjelmisto); keep it off some channels pyytää IPAWS-hälytysohjelmistoa jättämään pois radion ja TV:n, sääradion, puhelimet tai julkiset sivut.

Check näyttää CAP-viestin jonka se tekee ja mikä siinä on vialla, ja kuinka monta ihmistä se tavoittaa. Send kysyy vielä kerran, tarkan puhelintekstin ja alueen kera. Kun two-person approval on päällä, hälytys odottaa, kunnes toinen esimies painaa Approve (megafoni näyttää *to approve*); sen kirjoittaja voi perua sen, ja toinen esimies voi hylätä sen perusteluineen.

Voimassa

Voimassa oleva hälytys näkyy punaisena kartalla (keltainen testille) ja megafonissa, ja on julkisessa hälytyssyötteessä. Update lähettää uuden version samoille ihmisille joka korvaa sen; Cancel lähettää vaara ohi -viestin. Jokainen hälytys, hyväksyntä ja toimitus on tapahtumalokissa ja tehtävän aikajanalla.

IPAWSiin itseensä lähettäminen (Wireless Emergency Alerts ja EAS) tarvitsee FEMAn sopimuksen ja viranomaisen oman hälytyksenluontiohjelmiston; bitdispatcher kirjoittaa viestinsä IPAWS-profiiliin kyseiselle ohjelmistolle, ja tarkistaa ne Googlen CAP-kirjastolla ja sen IPAWS-profiililla sekä EAS Stationin syötteenlukijalla. Yhtään viestiä ei ole lähetetty IPAWSiin.

Luku 97

Itsepalvelukäyttöönotto

Viranomainen voi ottaa bitdispatcherin käyttöön itse, ilman että ketään ulkopuolista on paikalla. Kaikki määritetään admin-näytöillä, ja käyttöönoton tarkistuslista (luku 98) näyttää, mitä on jäljellä. Tuki, olipa se yhteisötukea tai tukisopimuksesta, on etätukea: sähköposti, puhelin tai videopuhelu.

Kuka tekee mitä

  • Järjestelmänvalvojasi työstää tarkistuslistan admin-näytöillä: kartta, asemat, yksiköt, tehtävätyypit, käyttäjät ja yhteydet.
  • IT-henkilöstösi ajaa palvelinta (tai kahta, toista sivustoa (luku 115) varten), sen varmuuskopioita ja sen varmennetta.
  • Puhelin-, radio- ja hakulaitetoimittajasi yhdistävät järjestelmänsä bitdispatcherin dokumentoituihin rajapintoihin: ALI-syötteet tai EIDO puheluihin, asemahälytysyhdyskäytävä, hakulaiteyhdyskäytävät. Kaikki, mikä vaatii käsiä, kaapeleita tai käyntiä paikan päällä, on heidän.
  • Se, joka tukee sinua, vastaa kysymyksiin ja lukee lähettämäsi tukipaketin (luku 100). Kenenkään ei tarvitse nähdä näyttöäsi tai kirjautua järjestelmääsi.

Toimiva järjestys

  1. Asenna yksi palvelin ja kirjaudu sisään järjestelmänvalvojana. Katso Aloittaminen (luku 1).
  2. Työstä tarkistuslista ylhäältä alas: Admin › Setup checklist. Kukin vaihe avaa sivunsa ja lukunsa täällä. Open the checklist (luku 98)
  3. Tuo vanhan järjestelmän data: kohteet ja vaarat, tehtävätyypit ja hälytyskortit ja, jos haluat ne, aiemmat tehtävät (Siirto (luku 118)); hälytysluvat (Hälytysyhtiöt & luvat (luku 91)).
  4. Harjoittele Training-tilassa: kopio järjestelmästä, jossa mikään ei tavoita todellisia yksiköitä. Katso Koulutus (luku 71).
  5. Aja vanhan järjestelmän rinnalla muutaman viikon: kirjaa puhelut molempiin ja vertaa suosituksia ja aikoja.
  6. Läpäise go-live-tarkistus: Admin › Go-live check. Korjaa se, mikä epäonnistuu, ja aja se uudelleen. Open the check (luku 99)
  7. Vaihda hiljaisena hetkenä, vanhan järjestelmän yhä pyöriessä vain luku -tilassa yhden päivän.

Varmuuskopiot

Tapahtumaloki (luku 54) on järjestelmä: jokainen asetus, yksikkö ja tehtävä rakennetaan siitä uudelleen. Kopioi koko datahakemisto palvelimelta joka yö, säilytä useita öitä, ja palauta silloin tällöin yksi varakoneelle ja kirjaudu sisään. Toinen sivusto ei ole varmuuskopio: virhe kopioituu molempiin kerralla. Go-live-tarkistus todistaa, että tapahtumaloki toistuu uudelleen; se ei näe muualla säilytettyjä kopioita, joten tarkistuslista pyytää sinua vahvistamaan ne.

bitdispatcher ei lähetä mitään BioDreamille tai kenellekään muulle itsestään. Tukipaketti poistuu järjestelmästäsi vain, kun järjestelmänvalvoja lataa sen ja päättää lähettää sen.
Luku 98

Käyttöönoton tarkistuslista

Verkkokäyttöliittymässä: /admin/setup

Admin › Setup checklist luettelee kaiken, mitä on tehtävä ennen ensimmäistä live-puhelua, järjestyksessä. bitdispatcher tarkistaa useimmat vaiheet itse työskennellessäsi: vaihe on valmis, kun sen sivulla on se, mitä se tarvitsee.

  • Required-vaiheet (pakolliset) on tehtävä ennen käyttöönottoa: viranomaisen nimi, tallennettu kartta, asemat, yksiköt, tehtävätyypit hälytyskortteineen, henkilöt (järjestelmänvalvojat todennussovelluksineen), ei esittelydataa, yölliset varmuuskopiot, koulutus ja läpäisty go-live-tarkistus (luku 99) viimeiseltä viikolta.
  • Recommended-vaiheet (suositellut) tekevät järjestelmästä paljon hyödyllisemmän: piirikunnan GIS, puhelinjärjestelmä, asemahälytys ja hakulaitteet, toinen sivusto, ajaminen vanhan järjestelmän rinnalla, ja kuka tukee sinua.
  • Optional: NCIC osavaltion viestinvälittimen kautta, jonka osavaltion CJIS-toimiston on hyväksyttävä.

Kukin vaihe kertoo, miksi sillä on merkitystä ja mitä bitdispatcher löysi (*3 stations; not on the map: Station 4*). Open menee sivulle joka tekee sen; ? avaa sen luvun.

Mark done on sille, mitä vain ihminen voi tietää: koulutus annettu, varmuuskopiot kopioitu palvelimelta, rinnakkaisajo valmis. Lisää huomautus jos haluat (*all three shifts*). Not needed on suositellulle tai valinnaiselle vaiheelle, jonka viranomainen jättää väliin, perusteluineen (*no paging: stations are alerted by radio*). Vaiheita, jotka bitdispatcher tarkistaa itse, ei voi merkitä tehdyiksi käsin. Jokainen merkintä on tapahtumalokissa, kuka sen teki; Undo peruuttaa sen.

Luku 99

Go-live-tarkistus

Verkkokäyttöliittymässä: /admin/golive

Admin › Go-live check ajaa automaattiset testit ennen ensimmäistä live-puhelua. Aja se uudelleen jokaisen suuren muutoksen jälkeen: uusi kartta, uudet asemat, uusi puhelinjärjestelmä. Run the check kestää muutaman sekunnin; tulos on tapahtumalokissa, ja käyttöönoton tarkistuslista (luku 98) laskee sen tehdyksi, kun mikään ei epäonnistunut viimeisellä viikolla.

Kukin testi läpäisee, sillä on jotain katsottavaa, tai se epäonnistuu:

  • Tapahtumaloki on ehjä: jokaisen tapahtuman tiiviste ja linkki, ensimmäisestä alkaen.
  • Tapahtumaloki palautuu: kopio tapahtumalokista toistetaan itsekseen ja verrataan käynnissä olevaan järjestelmään (asemat, yksiköt, tehtävätyypit, tehtävät).
  • Tilaa levyllä: epäonnistuu alle 2 GB vapaana, varoittaa alle 10 GB.
  • Ei esittelydataa: ei demoasemia, kohteita, tilejä tai NCIC-simulaattoria.
  • Järjestelmänvalvojat käyttävät todennussovellusta (CJIS pyytää toista tekijää).
  • FIPS 140-3 -salaus: hyväksytään, kun palvelin on käännetty komennolla make fips (Go Cryptographic Module, FIPS 140-3 -sertifikaatti #5247); muuten varoittaa. CJIS edellyttää validoitua salausta rikosoikeudellisille tiedoille.
  • Luotettu varmenne: varoittaa, kun palvelin käyttää omaa itse allekirjoittamaansa.
  • Tallennettu kartta kattaa jokaisen aseman.
  • Testipuhelut jokaisella asemalla: jokainen tehtävätyyppi hälytyskortteineen, jokaisella asemalla jolla on yksiköitä. Kukin lasketaan ja hylätään: mitään ei kirjoiteta tapahtumalokiin eikä yksikköön kosketa. Se varoittaa, kun ajoajat ovat suoria viivoja, kun toisen aseman yksikkö tulee ennen aseman omaa (syynä voi olla vastesuunnitelma (luku 107)), ja kun hälytyskortti pyytää yksiköitä, joita viranomaisella ei ole käytettävissä.
  • Puhelinjärjestelmä on yhdistetty, asemahälytys ja hakulaitteet toimivat (hälytys toimitettu viimeisten 30 päivän aikana) ja toinen sivusto kopioi (viimeisten 2 minuutin aikana).

Fix avaa sivun joka korjaa testin. Tarkistus ei koskaan hälytä, tekstaa tai tiedustele keneltäkään. Se ei voi nähdä muualla säilytettyjä varmuuskopioita, puhelinjärjestelmän omaa kaapelointia tai radiota: vahvista ne tarkistuslistalla.

Lue se ennen kuin lähetät sen. Nimi, jonka joku kirjoitti asetukseen tai tehtävätyypin ilmoituslistaan, jää. bitdispatcher ei lähetä mitään itsestään: lataat paketin ja päätät, lähetätkö sen ja kenelle. Jokainen lataus kirjataan tapahtumalokiin, kuka sen teki.

Luku 101

Viranomaiset

Verkkokäyttöliittymässä: /admin/agencies

Jokainen organisaatio, jolle keskus hälyttää, on agency (RPD, RCPD, SPD, RFD, RCFR, SFD, julkisten töiden osasto ja itse keskus): poliisi, palo ja ensihoito ovat toimialoja, eivät viranomaisia. Keskus ilman viranomaisia toimii yhtenä, keskuslaajuisin asetuksin.

  • Viranomainen: sen koodi ja nimi, toimialat, aktiivinen vai ei, ORI, NERIS ID ja muut tunnisteet, oma tehtävänumeron etuliitteensä, luokitukset, tilatarkastusajastimet, puheryhmät ja arkistosäännöt.
  • Mikä sille kuuluu: yksiköt, asemat, tehtävätyypit ja vastesuunnitelmat nimeävät viranomaisensa (listalta valittuna, ei kirjoitettuna). Viranomaisen vastesuunnitelma on vain sen tehtäville; sen ajastimet vain sen yksiköille.
  • Henkilöt: viranomaiset joilla kukin henkilö saa työskennellä, se jolle he tavallisesti työskentelevät, oletuksena katetut ja seuratut, ovatko he trainee, ja heidän rosterimerkintänsä. Joihinkin viranomaisiin rajattu henkilö muuttaa vain kyseisten viranomaisten konfiguraatiota ja näkee vain niiden esimiesnäkymät.
  • Workstations voivat kertoa mitkä viranomaiset ne kattavat ja seuraavat (Admin › Workstations).

Muutoshallinta

Konfiguraatiomuutokset voidaan luonnostella harjoitustaululla, kokeilla siellä, ja julkaista live-taululle perusteluineen, kaikki kerralla tai yhdelle viranomaiselle vain: yhden viranomaisen julkaisu ei koskaan kanna toisen tai keskuksen muutoksia. Kukin julkaisu säilyttää korvaamansa versiot: Roll back palauttaa aiemman hyväksytyn version, perusteluineen, ja se itse kirjataan.

Luku 106

Tehtävätyypit ja hälytyskortit

Verkkokäyttöliittymässä: /admin/calltypes

Suositukset täyttävät hälytyskortin. Kyvykkyydet tulevat yksikkötyypeistä (Admin › Settings) ja yksiköistä.

Critical call laittaa sellaisen parissa työskentelevät henkilöt esimiehen hoitolistalle (luku 69); Send a drone antaa lennokin lähetyssäännön kysyä lennokkia (luku 65).

Auto-dispatch (vain prioriteetin 3–5 tyypit): kun yksikään päivystäjä ei ole lähettänyt yksiköitä Settingsin odotusajan sisällä (60 sekuntia ellei muutettu), suositellut yksiköt menevät itsestään, kirjattuna *auto-dispatch*. Vain täydellinen suositus ilman varoituksia lähetetään (vahvistettu sijainti, jokainen rivi täytetty); muutoin aikajana kertoo miksi ja päivystäjä lähettää sen. Se yrittää kerran tehtävää kohden.

Luku 107

Vastesuunnitelmat

Verkkokäyttöliittymässä: /admin/plans

Response plan on hälytysjärjestys: yksiköt jotka viranomainen haluaa, määräysjärjestyksessä, kun suunnitelma soveltuu. Suositus noudattaa suunnitelman määräysjärjestystä kun yksi soveltuu; jos suunniteltu yksikkö ei pääse, se kertoo miksi ja kuka menee sen sijaan. Henkilö päättää aina.

Suunnitelma soveltuu kun kaikki sen ehdot täsmäävät tehtävään:

  • Call types: valitut koodit (tyhjä tarkoittaa jokaista tyyppiä).
  • Modifiers: valitut modifierit, jos ollenkaan.
  • First-due station area: aseman alue tai Anywhere.
  • Addresses: tehtävän osoite alkaa yhdellä näistä riveistä (yksi per rivi), osoitekohtaista suunnitelmaa varten.
  • From / To: vuorokaudenajan ikkuna (HH:MM), valinnainen.

Määräysjärjestys on yksikkötunnukset siinä järjestyksessä kuin ne halutaan; lisää listalta, järjestä uudelleen ylös- ja alas-painikkeilla, poista mikä tahansa. Suunnitelma ilman järjestystä ei kavenna mitään ja ohitetaan.

Luku 108

Kartan tallentaminen

Verkkokäyttöliittymässä: /admin/map

bitdispatcher tallentaa OpenStreetMap-datan keskuksesi ympärillä olevalle ympyrälle omaan tietovarastoonsa, piirtää sitten hälytyskartan, reitittää yksiköt teitse ja löytää osoitteet tuosta tietovarastosta ilman internetiä.

  1. Valitse keskipiste (esiasetus, konsolin kartan keskipiste tai sijainti) ja säde (100 mailia kattaa piirikunnan ja sen keskinäisen avun naapurit).
  2. Alueen tarvitsemat lataukset listataan heti (osavaltioiden poiminnat Geofabrikista). Paina Record.
  3. Tallennus kestää muutaman minuutin; hälyttäminen jatkuu nykyisellä kartalla, joka pysyy kunnes uusi on valmis. Kukin tallennus on tapahtumalokitapahtuma.

Bring up to date soveltaa OpenStreetMapin päivittäiset muutostiedostot (Geofabrik julkaisee yhden päivässä per poiminta) kartan tallentamisen jälkeen: muutama megatavu kokonaisten poimintojen sijaan, sitten tietovarasto rakennetaan uudelleen. Tallenna uudelleen uutta aluetta varten, tai kun kartta on yli vuoden jäljessä; jo tehdyt lataukset tarkistetaan julkaistuja tarkistussummiaan vasten ja käytetään uudelleen.

Automatic updates

Automatic updates tekee saman aikataulun mukaan: pois, päivittäin tai viikoittain, valitsemallasi tunnilla, viranomaisen aikavyöhykkeellä (Admin › Call entry rules › operational periods).

  • Uusi kartta rakennetaan käytössä olevan rinnalle, joka jatkaa toimintaansa koko ajan. Siihen vaihdetaan vasta kun se on valmis eikä ole menettänyt enempää kuin asettamasi prosenttiosuus (oletuksena 10) tiesegmenteistään tai osoitteistaan; vioittunut muutostiedosto näkyy kadonneina teinä, ja se evätään.
  • Ajo joka epäonnistuu, jolla ei ole internetiä tai joka havaitsee tallennuksen olevan jo käynnissä, jättää käytössä olevan kartan ennalleen, ja seuraava ikkuna yrittää uudelleen. Epäonnistunut aikataulutettu ajo viestii esimiehille ja ylläpitäjille.
  • Kukin ajo on tapahtumalokissa. Paneeli näyttää seuraavan ajon ja viimeisimmän lopputuloksen, kuten myös Jatkuvuus (luku 75)-sivu.

Ilmakuvat

Kartan alla Aerial photos tallentaa kuvat saman keskipisteen ympärillä: täysi tarkkuus valitsemasi säteen sisällä (zoom 19: katot ja autot) ja vähemmän reunaa kohti (zoom 16). Estimaatti (ruudut, koko, aika) seuraa lomaketta; jo tallennetut ruudut ohitetaan, joten pysäytetty tallennus jatkuu siitä mihin jäi. Lähteet ja niiden ehdot listataan: VGINin Virginia Base Mapping Program Virginialle, USGS The National Map (NAIP, public domain) muualla.

Luku 111

Integraatiot

  • Radio: salaisuus radiowebhookeille osoitteeseen /api/radio/events.
  • ALI spill: TCP-osoite jota bitdispatcher kuuntelee, ja Test.
  • Hooks, drones and translation: liitäntätunnus litteroinneille, kolaridatalle, lennokkiraporteille ja radiosanoille, lennokkijärjestelmä ja valinnainen kielimalli. Katso Liitännät ja yhteydet (luku 78).

  • Mapillary: client-tunnus Mapillaryn kehittäjähallintapaneelista.
  • Google Street View link: vain linkki.

Luku 114

Työasemat

Verkkokäyttöliittymässä: /admin/workstations

Workstation on yksi viranomaisen konsolipaikoista. Työasemaksi rekisteröity selain kirjautuu sisään siihen, eikä keneltäkään kysytä millä konsolilla he ovat: jokainen toimi kirjataan paikan ollessa jo tiedossa.

  • Add työasema lyhyellä tunnuksella (CT1, DISP2) ja halutessasi nimellä sille missä se sijaitsee.
  • Duties offered kaventaa mitä kyseisen paikan sisäänkirjautuminen saa ottaa: Call-taker, Police, Fire tai EMS dispatcher, Dispatcher (all disciplines), Supervisor, Administrator, Records. Älä valitse mitään tarjotaksesi jokaista tehtävää.

Luku 115

Useita sivustoja

Verkkokäyttöliittymässä: /admin/sites

bitdispatcher toimii kahdella tai useammalla sivustolla, kaikki live yhtä aikaa: pääkeskus ja varakeskus, tai naapuripiirikunnat jotka jakavat järjestelmän. Ei ole ensisijaista josta vikasietokytkentä tehtäisiin.

  • Kukin sivusto kirjoittaa oman tapahtumalokinsa ja kopioi muiden omat https:llä, joka sekunti, kukin tapahtuma tarkistettuna sivustonsa tiivisteketjua vasten ennen kuin se säilytetään.
  • Sama kuva kaikkialla: jokainen sivusto soveltaa kaikki tapahtumat samassa järjestyksessä (ajan, sitten sivuston mukaan), joten sivustot joilla on samat tapahtumat näyttävät saman tilan, missä järjestyksessä ne saapuivatkin.
  • Katkaistuna sivusto jatkaa toimintaa omillaan; kun yhteys palaa, tapahtumat vaihdetaan ja molemmat sivustot asettuvat samaan tilaan. Jos kaksi sivustoa muutti samaa yksikköä sillä välin, myöhempi muutos voittaa, molemmilla.
  • Tehtävänumerot kantavat kunkin sivuston etuliitteen (N26-000001, S26-000001), joten kaksi sivustoa eivät koskaan anna samaa numeroa.
  • Käyttöönotto: anna tälle sivustolle nimi ja etuliite ja tallenna; kopioi sen tunnus ja varmenteen sormenjälki muille sivustoille. Lisää kukin muu sivusto osoitteineen, tunnuksineen ja sormenjälkineen (Read it lukee varmenteen; tarkista se sitä vasten joka näytetään kyseisellä sivustolla). Tilarivi näyttää kuinka monta sivustoa on linkitetty.
Sivuston nimi ja etuliite kirjoitetaan jokaiseen tapahtumaan jonka se tekee, joten niitä ei voi muuttaa kun ne ovat käytössä.
Luku 116

Admin: jatkuvuus ja ylivuoto

Verkkokäyttöliittymässä: /admin/continuity

Mitä Jatkuvuus (luku 75)- ja Ylivuoto (luku 76)-sivut käyttävät.

Internet-tarkistukset

Enintään 10 https-osoitetta, joita bitdispatcher kysyy joka 30 sekunti (10–600); minkä tahansa yhden vastaaminen tarkoittaa, että internet toimii. Valitse sellaiset, joihin keskus nojaa: osavaltion viestikytkimen portaali, hakulaitepalvelun tarjoaja, suuri julkinen sivusto. Ilman yhtäkään asetettuna konsolit eivät voi sanoa, onko internet pystyssä; BitVoice, muut sivustot ja ylivuodon naapurit tarkistetaan joka tapauksessa.

Varakeskukseen siirtyminen

  • Checklist: yksi vaihe riviä kohti, kuitattuna Jatkuvuus-sivulla kun keskus siirtyy.
  • Contacts: varakeskus, naapurit, puhelinyhtiö, 911-viranomainen; tulostettuna jatkuvuuspakettiin.

Jatkuvuuspaketti

Kuinka usein se kirjoitetaan (1–240 minuuttia, tai ei aikataulun mukaan) ja enintään 5 kansiota, täysinä polkuina, datahakemiston vieressä. Tiedostot ovat luettavissa vain palvelimen tilillä.

Ylivuoto

Lisää ensin naapuri kohtaan Admin › Integrations › Neighbouring agencies, sen CAD:n osoitteen kera (https://their-cad/api/cad/eido/(heidän antamansa tunnus)) ja tunnus kumpaankin suuntaan; jos heidän varmenteensa on heidän omansa eikä viranomaiselta, lisää sen SHA-256-sormenjälki kiinnittääksesi sen. Sitten, kullekin naapurille:

  • We may ask them to take our calls, ja they may assign our units sillä aikaa kun he tekevät niin.
  • We take their calls when they ask, ja accept their requests on our own sopimukselle, joka sanoo kyllä etukäteen.
  • Our agencies, joiden puolesta he saavat ottaa puheluita (tyhjä: kaikki; yhdellä, heidän puhelunsa ovat sen tehtäviä ja vain sen yksiköt jaetaan), ja call types, joita he saavat käyttää (tyhjä: kaikki).
  • An overflow lasts 240 minuuttia, ellei toisin asetettu tai päätetty.
Sovi ylivuodosta kirjallisesti naapurin kanssa, ja 911-viranomaisen kanssa, joka asettaa puhelinverkon vaihtoehtoisen reitityksen, joka lähettää 911-puhelut yli.

Luku 119

Hyväksytty ohjeistus

Verkkokäyttöliittymässä: /admin/guidance

Approved guidance on viranomaisen käytännöt, puhelunkäsittelyoppaat, vasteoppaat ja tarkistuslistat. Hätäkeskuspäivystäjän Resources-välilehti näyttää täsmäävät passages-kohdat viittauksineen; mitään ei keksitä, vain hyväksytty teksti näytetään.

Asiakirjalla on tunnus, otsikko, kind (Policy (mandatory), Guide, Prompts tai Checklist), versio, voimaantulopäivä, valinnainen vanheneminen, mitä se korvaa, ja lähde josta koko hyväksytty kopio on. Rajaa se tehtävätyyppeihin, modifiereihin tai sanoihin, tai merkitse se always shown. Vain asiakirja joka on merkitty Approved for use näytetään hätäkeskuspäivystäjille.

Teksti on Markdownia otsikoilla #/##/###. Otsikot jakavat sen kohtiin. Otsikon alla rivi kuten Applies: CARD, CHEST; modifiers: WEAPONS; words: not breathing kaventaa kyseistä kohtaa.

  • Add the examples lataa selkeästi otsikoidut esimerkkiasiakirjat luonnoksina (ei hyväksyttyinä), nähdäksesi miten se toimii.
  • Try it täsmää tehtävätyypin, modifierit ja jotain tekstiä ja näyttää kohdat jotka hätäkeskuspäivystäjä näkisi, otsikkonsa, kindinsa, versionsa ja syynsä kera, tai huomautuksen kun mikään ei täsmää.

Asiakirjan tila on merkki: hyväksytty tai luonnos, ja vanhentunut kun sen vanheneminen on ohitettu.
