Get it

Try it in your browser, or install it yourself

bitdispatcher is built and tested, not yet in service anywhere. Try the live demonstration, or build it from source with Go and install it on Windows, Linux or macOS. There is no release to download yet.

The live demonstration

ICON:play Open the demo

Press Sign in as the demo user on its sign-in page, or sign in as demo with password try-bitdispatcher-demo. It is a dispatcher's console: everything on the console, the screens and the mobile terminal, but not the administration. The data is invented, around Roanoke, Virginia; simulated 911 calls arrive every 35 seconds; it goes back to the morning's incidents every night.

Build and run

Go 1.26 or newer, and Node 24 with corepack (pnpm) for the web interface.

git clone https://github.com/BioDream-LLC/bitdispatcher && cd bitdispatcher
make web build sim
./bin/bitdispatcher -demo      # https://localhost:8443; the first start prints the admin password once
./bin/bvsim                    # optional: a simulated BitVoice with 911 calls and radio traffic

-demo adds fictional stations and units around Roanoke, labelled as demo data. Then, in the browser:

  • Admin › Map: record the map for your area; the centre and radius are chosen on the map
  • Admin › Units, Stations, Call types & run cards: your agency
  • Admin › Integrations: BitVoice or another call-handling system; for the simulator, https://127.0.0.1:9444 with the token bv_simulated, then Read it to pin its certificate

The program is pure Go with no C libraries, built for Linux, macOS and Windows on Intel and Arm. make fips builds it with the Go Cryptographic Module under FIPS 140-3 certificate #5247, for agencies whose CJIS Systems Agency asks for validated cryptography.

Install it

Each installer sets bitdispatcher up as a service that starts with the computer, before anyone signs in, and shows the first administrator's password once, at the end. Every console then opens it in a browser. A newer installer upgrades it and keeps the records, the settings and the users; uninstalling keeps the records unless you confirm twice. Build the installers with one make after the steps above; they are written to bin/.

  • Windows (64-bit, desktop or Server): make windows, with NSIS, builds bitdispatcher-setup.exe. A wizard with the port and the records folder, a firewall rule, Start menu entries including Reset admin password, and a silent install for IT: /S /PORT=8443 /DATA=D:\bitdispatcher /NOFIREWALL.
  • Linux (systemd, Intel and Arm): make linux builds a .deb, an .rpm and a .tar.gz with install.sh. A hardened service under its own user; settings in /etc/default/bitdispatcher.
  • macOS 12 or later (Apple silicon and Intel): make macos on a Mac builds one .pkg. A launchd service under its own hidden account that keeps the Mac awake, and Applications › bitdispatcher with the console, Reset admin password, Uninstall and the manual.

Every option, and how to reset a lost password: Installing it in the manual.

What has been tested: Windows on one desktop computer and Windows Server 2022 in CI; the Linux Intel packages in Debian 12 and Red Hat UBI 9 with systemd and on Ubuntu 24.04 in CI, the Arm packages only on an emulated Arm processor; macOS on one Apple silicon Mac and in CI, not yet on an Intel Mac. The installers are not signed yet: Windows SmartScreen warns, and macOS asks before opening a downloaded .pkg (Privacy & Security › Open Anyway).

Set it up yourself

Everything is configured on the admin screens, and nobody needs to come on site. Admin › Setup checklist shows what is left before the first live call, Admin › Go-live check tests the result (the ledger, a restore, a test call of every call type at every station, the connections), and Admin › Support builds a support bundle with no secrets and no caller data for whoever helps you. Support is remote: e-mail, phone or video. Your own staff and your phone, radio and paging vendors do anything that needs hands. bitdispatcher sends nothing anywhere by itself.
